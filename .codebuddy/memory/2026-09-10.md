## 阴影后续：PCSS / Per-Object HQ Shadow 规划（仅分析，未改代码）

用户提供的 3 个 URP 文件（来自 Exillium2 项目，已读）：
- `AKG4e3_pcss_MEMORY.md`：Per-Object HQ 阴影（PCSS）最终设计总纲。
  算法：Blocker Search → 相似三角形半影半径(限幅 min(...,8)、pow、≥1texel、按命中比例淡入) → 变半径 PCF；
  bias 三件套：`_HQShadowPadding`(基础) + `slopeBias`(随斜率&核半径) + `normalBias`(沿法线偏移着色点)；
  旋转角用 IGN 式小参数哈希（不能用大整数 sin，会精度退化）。
- `sh_ReceiveHQShadow_test.shader`：URP 独立接收测试 shader，内联 PCSS 函数。
- `PerObjectShadow_RF.cs`：URP RendererFeature/Pass 驱动；用隐藏正交相机 `_HQShadowCamera` 拟合主光正交投影，
  画 `DepthOnly` 到小 RT，传 `_HQShadowDepthTex/_HQShadowVP/...` 全局；接收端 `min(hqShadow, mainLight.shadowAttenuation)`。

关键结论：
- 用户优先做「整体 PCSS」= 直接把 PCSS 算法接进现有主光级联 atlas 采样（`Shadows.hlsl` 的 `GetCascadedShadow`），
  不需要新 RT/相机/pass，只需 `Shadows.cs` 传少量参数。**不用搬 C#**。
- per-object 版是第二优先：壳（RendererFeature/RendererPass/RTHandle/RenderingData/隐藏相机）全部要换成
  自定义管线等价物（仿 Lighting/Shadows 的类 + GetTemporaryRT + 手动构造 ortho 矩阵）。
- 移植整体 PCSS 要点：tile 边界必须 clamp（图集每灯一行、每级联一列，大半径会串到隔壁 tile）；
  与 Soft/Dither 级联混合叠加会让采样翻倍；半径建议用纹素单位；深度可直接用 positionSTS.z 比。
- 自定义管线目前 `Lighting.SetupLights` **未记录主光**，per-object 阶段需要补这个输出。

阶段规划：阶段0 前置(Lighting暴露主光)；阶段1 整体PCSS(1~2轮)；阶段2 Per-Object HQ(2~3轮)；阶段3 可选屏幕空间降噪 blur。

## PCSS 决策（用户已确认）
- 范围：**只给主定向光**做 PCSS（4 个灯全做太贵）。实现：shader 里 `directional.tileIndex < _CascadeCount`
  即主光（灯块偏移=灯序号×级联数，第0个有阴影定向光偏移为0），无需新增传参。
- 距离单位：**用世界空间距离**（不用纹素）。每级联 `orthoWidth = 2*sphereR` 存进 `_CascadeData.z`；
  深度比值里 `2*orthoDistance` 会自动约掉，深度比较仍用归一化 `positionSTS.z`。
- 级联混合：**保留 Soft/Dither**（过渡带 PCSS 会跑两次，成本已接受）。
- 参考文章（ToyRP PCSS）：世界单位、16点泊松盘、2x2 屏幕块共享旋转、结果输出 R8 → 横竖两趟带 worldPos 权重 blur → lighting 采样。
- 采样数分级：可选但非必须；注意半径是世界单位时"远级联纹素半径更小"，真要分级是近级联多、远级联少。先统一 16+16。
- 第3步顺序：**forward 需要 depth-only prepass**（现在深度纹理是 opaque 之后才 copy，光照前拿不到）；
  **deferred 不需要**（GBuffer pass 先写几何，插在 GBuffer 与 deferred lighting 之间即可）。
- 屏幕空间通道：主光=单通道 R8；若将来多灯=RGBA 四通道。

## PCSS 级联切换跳变：搜索半径"纹素归一化"（2026-09-10 已实现）
诊断结论：异常与 blocker 搜索半径强相关、与三个 bias 无关、只在级联切换处、与 blend 模式无关。
根因：搜索半径用**世界单位**，而相邻级联纹素世界尺寸差约 2 倍 → 细级联覆盖很多纹素(找到远处blocker→半影偏大)、
粗级联不足1纹素(全有全无) → 同一点在两级联的 blocker 估计不一致 → 切换处跳变。
（`filterRadius=0.01` 部分缓解；`searchRadius` 调到最小可完全消除 → 佐证。）
修复：`Shadows.cs` 记录 cascade0 纹素世界尺寸 `pcssTexelWorld0`，上传
`_DirectionalPCSSSearchTexels = pcssSearchRadius / pcssTexelWorld0`；shader 里
`searchUV = searchTexels * _ShadowAtlasSize.y`、`searchWorld = searchTexels * texelWorld`（bias 用）。
参照：蛋白胨文章用 `blockerSearchWidth = 20 * OrthHalfWidth0/OrthHalfWidth` 做同类归一化，
并强调 bias 必须正比于(核半径×纹素世界尺寸/tanθ)（我们已有，但两处 cap 仍为 depthRange*0.05）。
遗留：若归一化后仍有跳变 → 粗级联分辨率限制，需上第3步（屏幕空间 PCSS + 保边模糊）。

## 补充结论：PCSS filterRadius 各级联响应不一致（仅分析）
原因：模糊半径是世界单位，但 shader 里 `radiusUV = max(radiusUV, 1 纹素)` 是硬下限，而"1 纹素的世界尺寸 = 2*sphereR/tileSize"逐级联约翻倍
→ 粗级联在 `filterRadius` 小值区被下限钉死（完全不变），细级联立刻响应 → 看起来"变化速率不同"。
次要因素：`ratio`/`hitFade`(blocker 估计对分辨率敏感)、`maxKernelUV`(tile 限宽)各级联截断位置不同。
可选修法：把下限换成可调的**世界单位**最小模糊半径（或去掉下限）；关掉 `pcssContactHardening` 可纯化验证只剩下限一条原因。

## 已修复：PCSS 在级联球边缘"阴影整块缺失"（根因=CPU 缩小剔除球）
现象：PCSS 开启后，每个级联球边缘一圈阴影消失，**左右两侧最明显、正前方不缺**；搜索半径越小越轻、越大越重；PCF 无此现象。
根因：`Shadows.cs.SetCascadeData` 在 pcss 开启时用 `cullMargin = max(texelSize, pcssSearchRadius)` 收缩 `cullingSphere.w`（米级世界单位）。
级联球彼此**不嵌套**（各自是视锥一段的包围球）：相邻球沿光轴有约 9 单位重叠（要缩 2s>9.17 才裂），但在切片分界处球与视锥侧边**恰好相切、侧向余量=0** →
任何收缩立刻在左右两侧露出"不被任何球覆盖"的环带 → `Shadows.hlsl GetShadowData` 走到 `i == _CascadeCount` → `data.strength = 0`
→ `GetDirectionalShadowAttenuation` 走 `directional.strength*global.strength<=0` 分支 → 取 baked（无 mask 即 1）→ 阴影消失。搜索半径还叠加了 `max(sr, 2*pcssTexelWorldMax)` 下限，放大了裂口。
修复：`cullMargin` 改回只按 PCF 滤波核 `filterSize`（PCSS 的大核越界本就由 shader 端 `uvClampMin/Max + maxKernelUV` 夹在本 tile 内，C# 收缩是多余的）。
代价/遗留：核被 `maxKernelUV` 夹小的环带处，PCSS 软度会退化到接近 1 纹素，可能在原裂口处变成"一圈更硬的阴影"；
若要保软度，可改为**扩大正交投影**（`Ortho(-(R+s), R+s, ...)` + `orthoWidth = 2*(R+s)`，剔除球保持原始半径）而不是收缩剔除球，代价是同等 tile 分辨率下纹素变大 (R+s)/R。
用户实测：该修复"问题几乎解决了"。

## cascade blend / fade 复查（2026-09-10，仅 dither 那一处已改代码）
- **已修（真 bug）**：`CameraRendererPasses.hlsl` 的 deferred 光照 pass 里 `surface.dither = InterleavedGradientNoise(uv, 0)`，
  `uv` 是 0~1 屏幕 UV（不是像素坐标）→ IGN 退化成低频渐变（全屏只绕约 4 圈），dither 混合近似硬切。
  改为 `InterleavedGradientNoise(input.positionCS_SS.xy, 0)`（与 forward 的 `config.fragment.positionSS` 语义一致）。
- **fade 公式**：`f=1-cascadeFade`，`_ShadowDistanceFade.z = 1/(1-f²)`；`fade = saturate((1-d²/r²)*z) < 1 ⟺ d/r > 1-cascadeFade`。
  即 `cascadeFade` = 剔除球半径的外圈比例（0.1 → 外圈 10% 的壳）。用的是到球心的距离² → 等值面是**球面**，与真正的切片分界面（平面）不重合。
- **`insideNextSphere` 门是 cascadeFade 不好调的主因**：`data.cascadeBlend = (下一球包含该点) ? fade : 1.0`。
  级联球不嵌套，切片分界处的侧向"月牙区"（点在球 i 内、球 i+1 外，宽度约 0.9 世界单位）会把 fade 带切掉 →
  该处强制 1.0（硬切），且离开球 i 时可能一次跳到 i+2。Soft/Dither 都受影响。去掉这个门就会回到"越界采样→环形假阴影"。
- **两道淡出叠乘**：`data.strength = FadedShadowStrength(viewDepth, 1/maxDistance, 1/distanceFade)`，最后一级联再 `*= fade(球壳)`。
- **顺带发现（未改）**：deferred 里 `surface.depth = GTDepth`（0~1 深度缓冲值，非米），而 forward 是 `-TransformWorldToView(...).z`（米）→
  deferred 下 `maxDistance/distanceFade` 的视深度淡出恒为 1（形同失效），所以 forward/deferred 的阴影出界位置不一致。
  修法：`surface.depth = LinearEyeDepth(GTDepth, _ZBufferParams);`（与 `Fragment.hlsl` 用法一致）。
- **cascadeFade 取值建议**：Hard 下 `cascadeBlend` 被强制 1.0，cascadeFade 只作用于最外层 strength 淡出 → 0.05~0.1；
  Soft → 0.1~0.2；Dither → 0.05~0.15。调之前先定 `distanceFade`，否则两者互相掩盖。
- 安全性备注：`i += 1` 不会越界，唯一原因是最后一级联 `cascadeBlend` 恒为 1.0（`1.0 < dither` 为假）——属"靠不变量兜住"，改动那处要小心。
