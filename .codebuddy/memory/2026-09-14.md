### `_SourceTexture` 到底绑的是谁（2026-09-14，用户复问，答案已给出）

- `_SourceTexture` 只是**一个共用的全局槽位**，每次 blit 前渲染器都重绑：`Draw(from,to)` → `SetGlobalTexture(_SourceTexture, from)`；`DrawFinal` → `SetGlobalTexture(_SourceTexture, colorAttachmentId)`（代码注释："源始终是颜色附件"）。所以 FD 里"有时 `_CameraColorAttachment` 有时其它"= 你在点不同的 draw，不是纹理变了。
- 本项目里实际只有三种源：拷颜色（源=附件、目标=颜色快照）、送屏幕 `DrawFinal`（源=附件、目标=屏幕）、深度拷贝（源=`_CameraDepthAttachment`）。**拷颜色和送屏幕这两条源相同、只有目标不同。**
- 更正我之前的措辞：`_CameraColorAttachment` **不是"只写"**——它是"当前画面"，既被写也被读；真正"只在生成那一刻被写、之后只被读"的是 `_CameraColorTexture`（快照）。
- 为什么两条都读附件：blit 的源=想复制的东西、目标=写到哪里；送屏幕必须用附件（拷贝之后透明物又往附件上画了，附件更新）→ 用快照会丢透明物。

`SetRenderTarget` 是命令缓冲区的全局状态，`DrawProcedural` 不会自动还原 → 最后一趟把 RT 设成 `_SSRTex` 之后，紧接着用 `context.DrawRenderers(...)` 画的透明物就被画进了半分辨率的 `_SSRTex`（而且那张图没有深度附件 → 深度测试失效）。
**已修**：`DrawSSR()` 末尾 `SetRenderTarget(colorAttachmentId, Load, Store, gDepthId, Load, Store)`（Load 保住已画好的颜色和 GBuffer 深度）。**这是 PCSS 前向版早就有的写法（"恢复主渲染目标"那句），我这次漏了。**

**4) 用户问"要不要专门弄个 `SSRSettings ssrSettings` 字段"** —— 答：项目里 PCSS 就是这么干的（`Shadows.cs` 有 `ShadowSettings settings;` 字段，Setup 赋一次，Render/Cleanup 用），所以是既有套路；每帧改设置/改值都不会有问题（uniform 只是数值；"决定要不要建 RT"的开关也是每帧读、Cleanup 用同帧的值配对）。

## 下一步分析：SSR 怎么和 Lit 的高光结合（2026-09-14，已给用户方案，未动笔）

**关键结论：融合点 = `gi.specular`（即 `GI.hlsl` 的 `SampleEnvironment`）**
- 链路已核对：`GetGI(...)` → `gi.specular = SampleEnvironment(surfaceWS, brdf)` → `IndirectBRDF(surface, brdf, gi.diffuse, gi.specular)` 里 `indirectSpecular = giSpecular * IndirSpecFactor(...)`（`IndirSpecFactor` 才是 F0/grazing/surfaceReduction 那套 Fresnel 权重），最后整体乘 `surface.occlusion`。
- ⇒ SSR 必须在**"原始入射高光"层**混进去：`environment.rgb = lerp(environment.rgb, ssr.rgb, saturate(ssr.a * _SSRIntensity))`。
- ⚠️ **绝不能在别处再乘 Fresnel**（会双重加权、掠射角变暗）；SSR 会顺带继承 `surface.occlusion`（可接受）。
- 一处改动两边生效：forward 的 `LitPassFragment` 和 deferred 的 `LitPassFragmentGBuffer` 都走 `SampleEnvironment` ✓。
- 实现前提：`_SSRTex` / `_SSRIntensity` 的声明要挪到**两个 shader 都先 include 的 `CameraRendererPasses.hlsl`**（因为 `GI.hlsl` 在 `ScreenSpaceReflection.hlsl` 之前被 include；否则 GI 里用不到 `_SSRTex`）。

**⚠️ 时序硬伤：不透明 Lit 物在同一帧基本拿不到 SSR**
- SSR 的生成点 = "不透明 + 天空盒之后"（第二次 `CopyColorAttachments` 后）⇒ 不透明物（forward 的 Lit、deferred 的 GBuffer→GT4）**早就画完了**。
- deferred 更明显：间接高光在 **GBuffer 阶段**就算进 GT4 了（`GT4 = emission + IndirectBRDF(...)`），那时 SSR 图还没生成。
- 三条路：
  - **A. 1 帧延迟（最省）**：把 SSR 两张 RT 从"每帧临时图"改成**持久/双缓冲**（首次清成 0），Lit 侧一行 lerp 用上一帧结果。改动小、立刻能看；缺点是相机快转/物体快动时反射慢一帧。
  - **B. 只在透明接收面接（同帧、零延迟）** —— 就是架构原定路线（水面 shader 采 `_SSRTex`）✓ 建议先用它验证算法。
  - **C. deferred 正解**：GT4 不再打包间接高光，改成"**SSR 生成之后、透明之前补一趟全屏间接高光合成**"（用 GBuffer 的 normal/roughness/深度重算 env+SSR 并加进颜色附件）→ 同帧、精度也更好，但改动最大（新 pass + 改 GT4 编码 + 从 GBuffer 里移除 specular）。
- 另需 `_SSRIntensity` 当门控（0 = 等价于现状）：**不能靠 missingTexture 顶替**（那是 0.5 灰，a=0.5 会混进灰）。

### 补充问答（2026-09-14）：融合点细节 + GT4 现状 + 前向怎么做全屏合成

- **Q1**：对，`SampleEnvironment` 就改最后那 1~2 行：先把 `DecodeHDREnvironment(...)` 存成 `env`，再 `lerp(env, ssr.rgb, saturate(ssr.a * _SSRIntensity))`。**额外代价是"拿屏幕UV"**（该函数没有 uv 参数：`surface.position` 现算 `TransformWorldToHClip` + `_ProjectionParams.x` 翻转，或给 `Surface` 加 `screenUV` 字段）。
- **Q2 纠正用户的理解**：`GT4` **不是只存漫反射** —— `LitPass.hlsl` 的 `LitPassFragmentGBuffer` 里 `indirectColor = IndirectBRDF(surfaceWS, brdf, gi.diffuse, gi.specular)`（**漫反射+高光都在**）然后 `GT4 = emission + indirectColor`。`gi.specular` 确实是"现场算"的，但**算完就打包进 GT4 了**，光照 pass 只是把它读出来加一遍 ⇒ 它的时间点固定在 GBuffer 阶段 = SSR 之前。
  ⇒ C 方案 = **把"间接高光"从 GT4 里拆出去**（GT4 只留 emission + 间接漫反射，`IndirectBRDF` 要拆出一个 specular-only 的变体）+ **新加一趟全屏 pass**（SSR 之后、透明之前，加法混合写进颜色附件）：从 GBuffer 读深度/法线/roughness/metallic/albedo + occlusion，重建位置和 viewDir，重算 env+SSR 的间接高光并加上去。
- **Q3**：那趟全屏合成**只有延迟能做**（它要的是 GBuffer 那几样：深度 + GBuffer2 法线 + GBuffer3 roughness/metallic/occlusion + GBuffer1 albedo→F0）。**前向没有 GBuffer**（只有深度 + `_CameraNormalsTexture`，没有粗糙度）⇒ 前向不做事后合成，前向的物体就**在自己的材质里融合**（= 方案A，roughness 本来就在材质里，天然有；代价是 1 帧延迟）。

### 追加问答（2026-09-14）：uniform vs keyword、GetGI 两重载、GT4 拆分口径

- **`SampleEnvironment` 加 uv 变体**：用户提议 ✓（只在变体里放 SSR 采样+lerp）；我建议**用 uniform `_SSRIntensity` 而不是 keyword** —— `lerp(env, ssr, 0)` 数学上恒等，不需要真分支，也没有"keyword 翻倍变体 + 切换时变体切换卡顿"；代价只是没开 SSR 时白采一次半分辨率 `_SSRTex`（很便宜）。
- **`GetGI` 两个重载的实际情况（grep 确认）**：
  - `GetGI(float2 lightMapUV, ...)`：**在用的那个** —— 调用者 = `LitPass.hlsl` 的 `LitPassFragment`(前向) + `LitPassFragmentGBuffer`(延迟写GBuffer) + `GPUDrivenTerrain.shader`；`gi.diffuse = SampleLightmap(lightMapUV) + SampleLightProbe(surfaceWS)`。
  - `GetGI(float3 precomputedIndirectDiffuse, ...)`：**目前没有任何调用者**（备用重载，给"间接漫反射已算好"的场景）。两版只差 diffuse 来源，`gi.specular = SampleEnvironment(...)` 那行一样。
- **⚠️ GT4 的写入端有两处**：`LitPass.hlsl` 的 `LitPassFragmentGBuffer` **和** `GPUDrivenTerrain.shader`（都 `indirectColor = IndirectBRDF(gi.diffuse, gi.specular)` → `GT4 = emission + indirectColor`）⇒ "GT4 里有没有 specular"必须写入端与读取端（光照 pass / 新合成 pass）口径一致。
- **两种口径**：(i) **无条件拆** GT4（只放 emission+间接漫反射）+ 合成趟**常驻**（不开 SSR 时只算 env，数学上等价现状）→ 零 keyword、零同步风险，代价是多一趟全屏；(ii) **keyword 双模式**（不拆 / 拆+合成）→ 零额外开销但要维护变体 + 两处写入端同步。**建议先 (i)**。
- 另外：`IndirectBRDF` 要拆出一个"只算间接高光"的版本给合成 pass 用。

- **预期**：现在开 SSR 应该"画面和关掉时几乎一致，只多出 SSR 反射"；若开 SSR 后变暗 = 合成没生效（查 Composite 那趟在不在、RenderTarget 是不是颜色附件、`_UseScreenSpaceReflectionInDeferred` 是不是1）。

## 排查（2026-09-14）：开 SSR 后画面偏暗 / 高光消失

**代码复查结论：算式层面没找到 bug** —— `IndirectBRDF` 拆分代数等价、`SampleEnvironment` 变体没有双重 Fresnel、composite 输出 alpha=0、`Blend One One` 正确。所以"变暗"最可能来自**行为本身**：`lerp(env, ssr.rgb, saturate(ssr.a))` 用"镜面里的场景颜色"替换掉了"亮的环境反射（探针/天空）"，而 SSR 还是半分辨率 + 5抽头模糊 ⇒ 尖锐高光被抹平、整体偏暗。

**给用户的二分实验（一眼分清"链路 bug"还是"预期行为"）**：在 `SampleEnvironment` 的 3 参变体里临时改成 `return environment;`（不做替换）——
- 画面恢复正常 ⇒ 说明"GT4 只写漫反射 + composite 加法"这条链没问题，变暗就是 SSR 替换导致的（预期）；
- 画面还是暗 ⇒ composite 没生效（没跑 / 读不到 GBuffer / alpha 问题），去帧调试器查那趟。

**若确认是预期行为，调节手段（按推荐顺序）**：① 按粗糙度加权 `* (1 - smoothness)`（对金属仍全用 SSR）；② 加 `_SSRIntensity`（`SSRSettings` 新字段 + 上传）；③ 想保住尖锐高光只能靠全分辨率追踪/时域累积（不是 bug）。

**两个"真 bug"形态的区分**：变暗且**看不到任何反射** ⇒ trace 在"自信地命中错位置"（`ssr.a` 高但颜色暗/错），把 `_SSRTex` 打到屏幕看反射图；变暗但**能看到镜像** ⇒ 预期行为。
**小精度点**：composite 的法线来自 `_GBuffer2`（10位）、albedo 来自 `_GBuffer1`（8位线性）⇒ 极光滑的镜面高光会有微小偏差，不影响整体亮度。

## 阶段 0 第 12 步：SSR 整体强度 + 半分辨率追踪开关（2026-09-14 完成）

- **`SSRSettings`** 新增：`[Range(0,2)] float intensity = 1f`（Tooltip 写明 0=完全不采SSR）和 `bool traceHalfResolution = true`（Tooltip 写明只影响追踪）。
- **强度**：`_SSRIntensity`（声明在 GI.hlsl 的 `_SSRTex` 旁边，**不带 InDeferred** —— 将来前向/水面都用）；在 3 参变体里 `ssr.a = saturate(ssr.a * _SSRIntensity); environment = lerp(environment, ssr.rgb, ssr.a);`；上传放在 `SetSSRParameters()`（只在 useSSR 时调用也无所谓：没开时 flag=0，压根不采）。
- **半分辨率追踪**：追踪图尺寸 = `traceHalfResolution ? 半 : 全`，**倒手图恒半分辨率**；因此**必须多一套纹素尺寸**：新增 `_SSRTexTempBlurTexelSize`（纵向blur读倒手图用它；横向blur读追踪图继续用 `_SSRTexelSize`）—— 不拆开的话"全分辨率追踪"时纵向blur步长会大一倍。
  - 代价/收益：全分辨率追踪让反射边缘更准（不再有那不到1像素的偏移），但最终清晰度仍受半分辨率blur限制 ⇒ 看起来更"准"而不是更"清"。
- ⚠️ **asset 坑**：`intensity` 是新字段，旧 asset 反序列化 = **0 = 完全不采 SSR**（画面像"没生效"）。已在 `Argonara Render Pipeline Asset.asset` 的 `ssr:` 块写入 `intensity: 1` / `traceHalfResolution: 1`（但 Unity 会话里保存 asset 会以 Inspector 值为准覆盖）。**让用户确认 Inspector 里 intensity = 1**。

### 回退（2026-09-14）：半分辨率追踪开关已撤

用户实测"追踪用全分辨率除了更慢几乎没区别"⇒ 决定 trace 和 blur 都固定半分辨率。
- 删：`SSRSettings.traceHalfResolution`、shader 的 `_SSRTexTempBlurTexelSize`、C# 的 `ssrTexTempBlurTexelSizeId`、asset 里的 `traceHalfResolution`。
- 恢复：`AllocateSSRTextures` 里两张图都用 `bufferSize/2` + 单套 `_SSRTexelSize` 上传；V blur 回到 `_SSRTexelSize.y`；注释恢复"只有这一套尺寸"。
- **保留**：`SSRSettings.intensity`（`_SSRIntensity`，0~2）+ asset 里的 `intensity: 1`。
- 在 `AllocateSSRTextures` 注释里留了一句"实测全分辨率追踪除了更慢几乎没区别" —— 免得以后又想试。

## 诊断（2026-09-14）：SSR 的"闪点"和"强度不好调"

用户报两个现象：① 反射面上的高光小块会随视角高频闪烁；② `_SSRIntensity` 不好调（整体偏暗 + 近远强度不分）。

**① 闪点 = 经典 SSR firefly**：`_SSRTex` 是半分辨率 + 每像素 Bayer 抖动 + 单次命中采样；反射源是**未tonemap的HDR快照**，太阳高光那种像素能到几十 ⇒ 抖动后的单次采样一旦命中它就变成亮点、旁边没命中就变回暗 ⇒ 随相机移动高频闪。建议（性价比排序）：
1. **按 mip 采颜色**（颜色快照已有 mip 链，`copyColorMips`）：`SAMPLE_TEXTURE2D_LOD(_CameraColorTexture, ..., mip)`，mip 由粗糙度或"命中的屏幕空间距离"映射 ⇒ 把孤立亮点和邻居平均掉，同时就是 roughness→mip 的正解。
2. **firefly clamp**：拿局部平均（mip1 或 3×3）当参考，把单次采样 clamp 到 `avg * k`。
3. 多抽头（2~4 次不同偏移）平均；再后面才是时域累积。
4. 加大 blur 半径只是缓解。

**② 强度不好调，三个具体原因**：
- **`marchFadeStrength` 在他的 asset 里是 0** ⇒ "命中越靠射线末端越淡"完全关掉了 = 远近不分的第一嫌疑人（打开 0.5~1）。
- `alphaCalc` 的远景淡出是 `saturate(1 - hitZ * _ProjectionParams.w)` = **以相机 far 为基准**（far 通常 1000）⇒ 在几十米的近景场景里几乎不生效 ⇒ 建议改成以 `_SSRTotalRayLength`（或新参数）为基准。
- "偏暗"是 SSR **替换**了环境反射（探针/天空通常更亮）+ 半分辨率平均把高光摊平 ⇒ 建议加"按粗糙度加权"（粗糙面多保留 env）或"env 保留比例"参数；`_SSRIntensity` 只能整体缩放可信度，救不了亮度分布。

### 追加答疑（2026-09-14）：firefly 做法、远平面为何没影响、粗糙度加权怎么落地

- **多抽头** = 同一像素采 2~4 次、每次抖动相位不同再平均（贵，所以他在卡特莱克那篇里没见着）；**firefly clamp** = 用邻域平均/低 mip 当参考，把单次采样 `min(color, ref*k)` 压下去（便宜）。
- **卡特莱克 bloom 的 "fade fireflies" 能借鉴**：它用 `w = 1/(Luminance(c)+1)` **按亮度反向加权**做加权平均 —— 本质就是"软 clamp" ✓ 比硬 clamp 平滑、不看阈值。**落地建议**：把 SSR 那两趟 blur 的权重从纯二项式改成 `kernel[i] / (Luminance(SAMPLE) + 1)`，零成本、正对症（亮斑被摊平）；它原文也靠"后续高斯模糊收尾"，我们正好有那两趟。
- **为什么调相机 far 看不出变化**：`alphaCalc` 的远景淡出 = `saturate(1 - hitZ/far)`；10 米命中、far=1000 ⇒ 只淡 1%（HDR 下根本看不出）。要从"几十米"的基准来算才行 ⇒ 换成 `saturate(1 - hitZ / _SSRTotalRayLength)`（或单独一个几十米的参数）。**别急着改成二次函数**：一般做法就是线性 + 可调距离，看不出变化是基准太远，不是函数形式的问题。
- **偏暗的第二个根因**：粗糙面现在也会被 SSR 替换（而它本该用探针的模糊结果）。落地：`w = saturate(ssr.a * _SSRIntensity) * (1 - surfaceWS.roughness)`（`1-roughness` 就是 smoothness），粗糙面自然退回 env；想更柔和再乘一个"env 保留比例"（如 0.7）。**注意 `SampleEnvironment` 的 3 参变体里 surface 是现成的，直接可用。**

### 更正 + 结论（2026-09-14，用户纠正了几点）

- **多抽头**：用户判断对 —— 主流 SSR（HDRP/UE）是**每帧 1 条射线 + 时域累积**，一帧内对同一像素打多条射线代价太大。卡特莱克那招便宜是因为它作用在**降采样/模糊**上（9 个抽头是"采样"，不是打 9 条射线）；所以我们的落地版 = **把已有的 blur 5 个抽头换权**（按亮度反向加权），完全免费。
- **`marchPercent` 淡出 vs `hitZ` 淡出不重复**：前者是"命中点在这条射线上的进度"（分母 = `_SSRTotalRayLength`，衡量"沿反射方向离接收面多远"），后者是"命中点离相机的距离"（分母现在 = far，要改成固定距离）。效果上有重叠 ⇒ 建议分工：`marchPercent` 管前者，`hitZ` 的固定距离设大一点（只处理"整条反射都很远"）；只想留一个就留 `marchPercent`。
- **⚠️ 更正我之前的说法**：用户实测"**完全粗糙的面开不开 SSR 没区别**"（对：粗糙面的镜面权重被 `IndirSpecFactor` 压得很小），有区别的是**光滑面**。我之前说"粗糙面被 SSR 替换"措辞错了。
- **"SSR + 天空盒叠加"不能直接做**：SSR 快照本身包含天空盒，直接相加会把天空反射算两遍（亮一倍）。用户的直觉对应的**正确做法**是"**锐利部分给 SSR、模糊部分给探针**"= 镜面/粗糙分离 = `(1 - roughness)` 加权 ✓。
- **整体偏暗的主因**（修正版）：半分辨率 + 两趟模糊把**高光峰值摊平**（和"闪点"是同一件事的两面），不是"少了叠加"。想补亮度用 gain；想守住高光靠 mip 采样 / 亮度加权平均。

### 结论（2026-09-14）：hitZ 淡出不改 + "叠加 vs 替换"

- **hitZ 那项不改**（用户判断对）：原本是"到相机远平面才淡到0"，我建议改成 60~100m 会让反射更早变暗 ✗。真要区分远近，只能做成"far 之前一小段才开始淡"的可调项，别砍到 100m。
- **`_SSRTex` 里未命中的像素就是 0**（反射到天空的射线会被判交条件排除 ⇒ 不命中 ⇒ 输出0 ⇒ 接收面退回探针 ✓ 天空并没有丢）。所以在 `a = 0` 的像素上，"叠加"和"替换"**等价**（加0等于没动）。
- **但 `a > 0` 的像素上不能叠加**：那个方向本来只该有物体（SSR 命中它），叠加会变成"天空 + 物体"同时在 ⇒ 双重计天空 + 物体后面透出天空的鬼影 ⇒ 反射偏亮。
- **要给亮度就用 gain**（只乘 SSR 颜色）——"替换 + gain" 优于 "叠加"。

## 定案（2026-09-14）：firefly 与偏暗的最终处置

- **firefly 只做两条**：① `SampleReflectionColor` 改成 `SAMPLE_TEXTURE2D_LOD(_CameraColorTexture, ..., mip)`（mip 来源待定：命中距离或粗糙度）；② blur 两趟改成"亮度反向加权"（卡特莱克 `1/(Luminance+1)` 那招）。多抽头/时域以后再说。
- **偏暗 = 固有代价，不是 bug**：没有叠加、也没有双重计入（`ssr.rgb` 是那个方向的入射光，权重在 `IndirSpecFactor` 里乘一次）；偏暗来自"半分辨率+模糊摊平高光峰值 + SSR 替换了更亮的探针"⇒ 只能手动乘 gain（新增 `_SSRGain`，乘在 `SampleReflectionColor` 的返回值上，两个 pass 共用那一行）。
- `_SSRIntensity` 语义不动（命中可信度倍率）；gain 是新增的（反射亮度倍率）；两者独立、都在同一处。
- **为什么调 intensity 到 5 也不亮（2026-09-14 用户实测）**：有两处硬限制 ——
  ① `SSRSettings.intensity` 是 `[Range(0,2)]`，Inspector 上最多只能到 2（手写 5 会被夹回）；
  ② shader 里 `saturate(ssr.a * _SSRIntensity)` ⇒ **权重上限就是 1**，`lerp` 的极限是"完全用 SSR"。
  ⇒ 它只能加快"吃满 SSR"，**无法把 SSR 本身变亮**；要更亮只能用 gain 乘 `ssr.rgb`（也就是 `SampleReflectionColor` 的返回值）。
- **定案改动（2026-09-14）**：用户决定 `intensity` **直接当 gain 用** —— 不再动 alpha。实现：`GI.hlsl` 的三参变体里 `ssr.rgb *= _SSRIntensity;` + `lerp(environment, ssr.rgb, saturate(ssr.a));`（可信度只用 `ssr.a` 本身）。`SSRSettings.intensity` 的注释/Tooltip 改为"反射亮度倍率：0=反射全黑，1=原样，>1=更亮"；Range 保持用户自己改的 `[Range(0,5)]`。没有新增 `_SSRGain`（intensity 就是这个角色）。

## 概念问答：mip 生成到底是什么

- mip 生成 = 从 mip0 逐级降采样算出 mip1..N（每级尺寸减半，通常 2×2 box 平均）。
- "Blit/DrawProcedural 只写 mip0"的原因：渲染目标一次只能指向一个 mip 级（`SetRenderTarget` 的 mipLevel 参数，默认 0），其余级不会被写 → 里面是未初始化/上一帧数据。
- 两条路：① `autoGenerateMips = true`（每次写该 RT 后 Unity 自动跑，会被光照Pass那几次写白烧）→ 所以选 ② `autoGenerateMips = false` + 手动 `cmd.GenerateMips(id)`（引擎内置命令一条生成整条链，不需要自己写 pass）或逐级 blit。
- 时机：**最后一次写 mip0 之后、采样之前**。本项目 = 拷完"不透明+天空盒"快照之后（天空盒之后的透明物不会进 mip，和折射的既有语义一致）。
- 采样注意：静态采样器 `sampler_linear_clamp` 的 mip 过滤不保证三线性 → 想平滑就自己 lerp 两级（floor/frac），或用 Trilinear 的纹理自带采样器。RT 已建为 Trilinear。
