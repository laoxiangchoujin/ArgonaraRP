## 级联阴影包围球 Debug：从“渲染副作用缓存”改为“现算”（方案A落地）

背景/结论（分析阶段，未改代码，供后续参考）：
- Scene 视图的相机小预览窗 = 编辑器功能，渲染的是“选中相机的副本”（cameraType=Game），不是原相机。
- 级联球旧实现是 Shadows 渲染时（index==0 的光源循环内）把球缓存进按相机分 key 的 Dictionary；
  只有“该相机真实渲染了一帧”才刷新 → Scene 里只开 Game 视图才会出现球、球不跟随相机；且副本渲染刷不到原相机。

本次改动：
- `Shadows.cs`
  - 删掉 `debugCascadesByCamera` / `debugCascadeCountByCamera` 两个 Dictionary、`TryGetDebugCascadeSpheres`、
    Setup 里的清零行、`RenderDirectionalShadows` 里的缓存填充块；并删除 `using System.Collections.Generic`。
  - 抽出 `static void ComputeCascadeSphereGeometry(...)`（纯相机视锥+级联比例算球心/半径，不含灯相关部分），
    渲染路径 `ComputeDirectionalShadowMatricesAndCullingSphere` 与新增的
    `public static Vector4[] ComputeDebugCascadeSpheres(Camera, ShadowSettings)` 共用它，保证几何口径一致。
  - 注意：调试现算未含真实渲染里前4级联的 Anti-shimmer 纹素对齐（亚纹素级，无差别）。
- `ArgonaraRenderPipelineAsset.cs`：加只读属性 `public ShadowSettings Shadows => shadows;`（原来 field 是 private）。
- `ArgonaraRenderPipelineCamera.cs`：`OnDrawGizmos` 改为直接
  `Shadows.ComputeDebugCascadeSpheres(GetComponent<Camera>(), (GraphicsSettings.renderPipelineAsset as ArgonaraRenderPipelineAsset).Shadows)`，
  仅在 `cascadeDebug` 开启时画；不依赖实际渲染，Scene/Game/非播放模式都跟手。

## Soft/Dither 级联过渡出现“环形假阴影”诊断与修复
现象：纯平面、无遮挡物，Soft/Dither 下在各级联交界出现环状假阴影，基本只在画面左右两侧；
0/1、1/2、2/3 交界都有。Hard 正常。
根因：混合带的 fade 按“到当前级联球心距离”计算且球外接贴住相机近端→左右两侧地面点
先进入当前级联球边缘触发过渡，却还没进入“下一级联球”；Soft/Dither 直接越界采样下一级联的
shadowmap（该区域没有它的合法内容）→ 假阴影环。中心点已落入下一级联球所以干净。
修复（`Shadows.hlsl` `GetShadowData`）：else 分支先检查
`DistanceSquared(pos, _CascadeCullingSpheres[i+1].xyz) < _CascadeCullingSpheres[i+1].w`，
满足才 `data.cascadeBlend = fade`，否则强制 `1.0` 留在本级联。
