## 关键经验条目（两篇文章 + URP 实测，参数→现象）

- **断带 / 物体与反射之间的"玻璃缝"** = 一步跨过的深度 > thickness；近处天然没有、远处随距离变宽 ⇒ 正解 `thickness = max(_SSRPixelThickness, k*abs(rayStepB-rayStapA))`（在 `intersect` 内即可，无需改签名）。
- **相同颜色的拉丝** = 射线出屏 + clamp 采样（必须查 uv 越界）。
- **"钳制范围"/自反射圆圈** = 终点越过近平面 ⇒ 终点截断到近平面（两位作者都踩过）。
- **阶梯拉丝** = stride 太大 ⇒ 减小 stride + 提高步数（二分解决"跨过第一个交点打到第二个"的**准确**问题，不是性能）。
- **掠射反射淡** = ① 无 Fresnel（物理根因）② 命中晚/远（marchPercent、hitZ 两项衰减）③ 厚度太小漏检。
- **起点自交**：`prev 推 0.1 步`（用户版）或固定 0.1 米 bias（Thetus）；**"沿法线抬起起点"实测无用**（只会让反射像整体位移）。
- **命中判据三方一致**：`rayFarD >= surfaceD && rayNearD <= surfaceD + thickness`（保持，别改）。
- jitter 用 **4×4 Bayer**（就是 Thetus 那张表）；它带来的"小格子"靠后面的模糊抹掉。

## 我给出的三个必须先定的架构决策

1. **SSR 做成独立全屏 pass + 独立 RT**（半分辨率起步 + ping-pong 模糊），不再在物体 shader 里直接读颜色——这是能模糊/降噪/半分辨率/将来 Hi-Z 的前提。
2. **合成放在"接收面"**：
   - 不透明接收面（可选，后做）：在 deferred 光照阶段用 GBuffer 的 normal/smoothness + `F0*envBRDF.x+envBRDF.y` 加权；
   - **透明水面（首要目标）：水面自己的 shader 采样 SSR RT**，用自身法线贴图 + TBN + Fresnel/smoothness 做合成。
     ⇒ 同时绕开两个大坑："透明物体没有 GBuffer"、"哪些物体才反射"（Thetus 自评没搞定的那块）。
3. **相机颜色要带 mip**（roughness→mip 的前置）：现在 `CopyColorAttachments` 只拷贝、无 mip ⇒ 先预留接口，做 Glossy 时再换成带 mip + GenerateMips。

### 关于"能否复用 PCSS 的 blur / 塞进那个 shader"
- **不能直接复用**：① 算法不同——PCSS 那两趟是**双边**（每抽头 3 次采样，为阴影去噪），SSR 要的是**箱式/高斯**（反射图里的深度/法线跳变是内容，双边会吃掉细节）；② 图名写死（`_ScreenSpaceShadowTex`/`_ScreenSpaceShadowMaskTex`）；③ 纹素尺寸 uniform 不同（共用会互相牵制，正是之前"喂错尺寸→模糊半径错"的坑）。**mask blur 那两趟（纯箱式）**与 SSR 需要的算法同族，可照抄改图名。
- **不建议塞进同一个 shader 改名**：那个 shader 已 6 pass/470 行；它的 `_DIRECTIONAL_PCSS`/`_SHADOW_PCF3/5/7` multi_compile 对 SSR 全是白编的变体（用户在意编译时间）；枚举/索引会混在一起；与项目"一个屏幕空间特性一个 shader"的约定不符。⇒ **新建 `ScreenSpaceSSR.shader`**，沿用同套写法（SubShader 统一状态 + HLSLINCLUDE + pass 索引调用 + 渲染器里配 `enum SSRScreenPass`）。

## 三个问答结论（2026-09-13）

1. **roughness→mip 的出处**：**毅毅《SSR》系列**的**第 9 节"他自己列的 6 条后续方向"第 1 条（Glossy 效果）**——原话"给 CameraColor 生成 mip 链，用射线距离（或屏幕空间距离）当 mip level 做三线性采样"（他自称"瞎猜的"）。
   而"URP 的 `_CameraOpaqueTexture` 没有 mip"**不是文章说的**，是另一个 AI 查 URP 源码 + 用户 asset（`m_OpaqueDownsampling: 3` = 4xBilinear、不建 mip）得出的结论。**本项目自己管线里没这个限制**。
   做法：① 相机颜色拷贝改成带 mip（`GetTemporaryRT` 换 `RenderTextureDescriptor` 重载 + `mipCount` + `useMipMap` + `autoGenerateMips=false`，拷完 `GenerateMips`）；② 追踪时 `SAMPLE_TEXTURE2D_LOD(颜色, uv, mip)`，`mip` 由粗糙度（或命中距离/射线长度）映射；③ 之后两趟 blur 只负责抹 jitter 噪点，半径可调小。代价：GenerateMips 一次额外全屏 pass。便宜替代：让 blur 半径随 smoothness（读 `_GBuffer3.xyz`）变，零新资源但做不了"按命中距离变化"。
2. **PCSS 的总开关与 blur 开关独立 → 不应该；已按用户要求修好（2026-09-13）**：
   原来两个渲染器的门都是 `useScreenSpaceShadow = pcss.screenSpaceBlur && screenSpaceShadowMaterial`（**不含 `pcss.enabled`**），而且光照 pass 采样屏幕空间图的唯一门是全局 `_ScreenSpaceShadowEnabled`（**也不看 `pcss.enabled`**）。
   ⇒ `enabled=false + screenSpaceBlur=true` 时：4 张图照样建、5 趟照样跑、光照照样采 —— 等于"用屏幕空间那一趟算了一遍和普通 PCF 等价的东西"，性能白烧、画面不变。
   **已改（两个渲染器各一处，`CameraRendererForward.Setup` 与 `CameraRendererDeferred.AllocateScreenSpaceShadowTextures`）**：
   `useScreenSpaceShadow = pcss.enabled && pcss.screenSpaceBlur && screenSpaceShadowMaterial;` + 注释说明原因。lint 0 错误。
   三种组合自此自洽：enabled+blur=屏幕空间PCSS；enabled+!blur=逐物体算PCSS；!enabled=纯PCF、屏幕空间那套完全不创建。

3. **毅毅给的那段代码不是"opaque texture 建 mip"**（用户关键词搜到的两段）：
   - `m_Descriptor = cameraTargetDescriptor; useMipMap=false; autoGenerateMips=false;` = **明确关掉 mip** 的样板（他给自己 pass 的内部 RT 用），正好是"不建 mip"的反面教材。
   - `GetSource(uv) { SAMPLE_TEXTURE2D_X_LOD(_BlitTexture, sampler_LinearRepeat, uv, _BlitMipLevel); }` = URP `Blit.hlsl` 标准写法，说明他走的是**手动/逐级 blit 的 mip 链**（`Blitter.BlitTexture(..., mipLevel)` / `SetRenderTarget(rt, mipLevel, ...)`），**不是** `cmd.GenerateMips`。
   - ⚠️ 关键区分：他正文里的 **Hi-Z mip = 深度金字塔（加速求交/二分）**，和"**颜色** mip 链做粗糙度模糊"是两码事；那句"给 CameraColor 生成 mip 链"只是结语里的方向性建议（他自称瞎猜），所以他文章里**没有**颜色 mip 的完整实现 → 得我们自己写。
4. **本项目做"颜色 mip 链"的可行性结论（Unity 2023.2.20f1，用户问的 4 个点）**：
   - 容易：`CopyColorAttachments` 里把 `GetTemporaryRT` 换成 `GetTemporaryRT(int nameID, RenderTextureDescriptor, FilterMode)` 重载，描述符上 `useMipMap=true; autoGenerateMips=false; mipCount=N`，拷完 `buffer.GenerateMips(id)`。
   - 能控层数：能，`RenderTextureDescriptor.mipCount`（2023.2 支持）。
   - 能动态开关：能，**本项目比 URP 更好做** —— 每帧都 `GetTemporaryRT` 重建 RT，直接按设置切描述符即可（URP 那边 RTHandle 有缓存/重建成本）。
   - **`GenerateMips` 不需要新写 pass**：引擎内置 shader 一条命令生成整条链；只有想自定义每级滤波/省 blit 才自己写。
   - 坑：`useMipMap` 的 RT 用 `Blit`/`DrawProcedural` 只写 mip0；显存 +33%；半分辨率 4~5 级够用；mip0 必须是"未经后处理的相机颜色"（现在是"不透明+天空盒之后"的 HDR，✓ 正确）。
