## 📖 读了用户给的两篇（`毅毅_SSR_精简版.txt`、`毅毅的HiZ的文章部分.txt`）要点

- **Hi-Z 步进（原文）**：屏幕空间 DDA（沿主轴每步 `stride × 2^mip` 像素）→ 采**该级一格** → 远点越过表面（`rayFarZ <= surfaceZ`）时：
  **mip0 且 `abs(surfaceZ - rayNearZ) < thickness` ⇒ 命中**；**否则"位置退回一步 + mip−1"**（原文：高层级被遮挡先回溯、再小步迈进，直到回到第 0 层）；
  没越过 ⇒ `mip = min(mip+1, _MaxHiZMipLevel)`（步长翻倍）。
- **起点沿法线抬起 `rayOffset`（0.01 量级）**（治自交；太大 ⇒ "钳制范围"，太小 ⇒ 自反射）。
- **近平面截断**（`endVS.z > -near ⇒ 截短 maxDistance`）—— 两位作者都踩过这个坑。
- **出屏必须检查**（否则 Clamp 采样 ⇒ "拉丝"）。
- **⚠️ 调参坑（原文原话）**："我们的步长 Stride 和阈值 Thickness 都将使用**更高的参数**……如果使用原来的值会出现**非常严重的断层**。"
- **Hi-Z 图**：单通道 `R32_SFloat`；**各层尺寸取"大于屏幕的 2 的整数次幂"**（原文理由：准确对齐屏幕信息、提高降采样准确性）；6 级；
  用 **`FilterMode.Bilinear`** 的 RT（采样用 `sampler_HiZTex` = 带采样的 sampler）；采样时按**任意步位置**直接采该级。

  - ⏭ 若还不出现 AA（= 抖动还是没通），下一步用**土办法定位**：把 jitter 临时放大到 ±8 像素（画面抖起来=通了；不抖=没通）。
- ✅ **改成"Submit 之后还原"后用户实测：效果挺好了**（不糊 + 有 AA）⇒ TAA 移植完成（唯一没做的是运动矢量 / 锐化）。
- **三个参数的含义（`TemporalAntiAliasingSettings`，都在管线资产的 TAA 折叠项里）**：
  `blend = saturate(blendFactor + |motion| * motionBlendScale)`，是**当前帧的权重**（`lerp(历史, 当前, blend)`）。
  ① `blendFactor`（默认 0.05）基础权重：小 = 更信历史（稳、干净、但慢/软/易鬼影），大 = 更脆（清晰、噪点与爬行更多）；
  ② `motionBlendScale`（默认 100）：动得越多越信当前帧。`motion` 是 **uv 单位**（1 像素 ≈ 0.001）⇒ ×100 ≈ "1 像素运动 +0.09 权重"；
     动的东西拖影就调大，动的东西闪/噪就调小；
  ③ `sharpenStrength`（默认 0）：**目前 shader 没接**（仍在 SetGlobalFloat 上传、未使用）；觉得整体偏软再接"3×3 对比度自适应锐化"。

### ▶ 已做 ③ 锐化（2026-09-21，待实测）：`_TAASharpenStrength` 接上了

- 位置：shader 末尾、`lerp(历史, 当前, blend)` **之后**。做法 = **unsharp mask**：`result.rgb = max(result.rgb + (result.rgb - 邻域均值) * strength, 0)`。
- **不额外采样**：邻域和是复用上面 3×3 AABB 那 9 个抽头攒出来的（把 `sampled` 加进 `neighborhoodSum`）。
- `0` = 完全不变（默认 ⇒ 等于之前的行为 ✓）；建议 **0.1~0.4**，开大就有白边/过冲。`[Range(0,1)]` 没改。
- ⚠️ `_TAAResetHistory` 那条早退**不锐化**（那帧本来就只有当前帧、不需要补软）。
- 用户问"TAA 这个锐化能不能顶掉 PostFX 的锐化" ⇒ 答：**现在（TAA 在 tonemap 之前）能顶一部分但打折**
  （锐化发生在 tonemap 前、半径固定 1 像素、HDR 里过冲会被压）；**等第 2 条把 TAA 挪到 tonemap 之后，它就作用在最终画面上 ⇒ 那时完全可以替代 PostFX 的锐化**。

### 🗺 ② 「挪到 tonemapping 之后」的规划结论（2026-09-21，给用户分析过、等动手）

- 用户引用的文章顺序：`Reinhard Tonemapping → TAA → 还原 HDR → 其它 HDR 后处理 → 最终 Tonemapping`。
  **分析：这**不是**"把 TAA 排到最终 tonemap 之后"，而是"在 HDR 段里夹一个临时 Reinhard"** ⇒ 目的 = 让混合/AABB 在**压缩域**里做（高光不发散），最后仍由真正的 tonemap 收尾。
- 我们的链 vs 文章：几何/SSR/透明 → **TAA** → **Bloom**（HDR）→ **Final**（色彩分级 LUT + tonemap → 屏幕）。
  对应关系：文章的"其它 HDR 后处理" = 我们的 Bloom（已在 TAA 之后 ✓）；"最终 Tonemapping" = 我们的 `Pass.Final`（已在最后 ✓）
  ⇒ **位置其实已经一致，缺的只是"夹心"**。
- ⚠️ 澄清（用户以为要"SSR 后加一趟 Reinhard、TAA 后再加一趟反 Reinhard"= **额外两趟绘制**）：
  **不需要额外趟**。压缩/还原都是**逐像素的数学**（`c/(1+c)` 与 `y/(1-y)`，不需要邻居）⇒ 直接写在 **TAA 那一趟的 fragment 里**：
  ```hlsl
  float3 colorC = Reinhard(color.rgb);  float3 historyC = Reinhard(historyColor.rgb);
  ...AABB / ClipHistory / blend 用 C 版...
  float3 result = InverseReinhard(clamp(lerp(historyC, colorC, blend), 0, 0.999));
  ```
  结果和"多两趟"完全一样（还省两趟带宽/两张临时图，而且中间不必落进低精度 RT）。**只改 shader 的 fragment，C# 一行不动。**
- **决定（2026-09-21）**：② 只做"第 1 步（shader 里 inline 夹心）"；**第 2 步（历史图存压缩域）不做**（省不了多少、还把"历史图是什么"搞复杂）；
  **第 3 步（真把 TAA 挪进 PostFX）不做** —— 我们 postFX 的最后那趟 `Pass.Final` **就是 tonemap 且直接写屏幕**，要挪就得改 `PostFXStack`
  （Final 先写临时 LDR 图 → TAA → 拷屏幕，还要处理 renderScale 的 `finalResultId/FinalRescale` 与分屏 viewport），而且是"LDR 域 TAA"，和文章那套（HDR 里夹心）不是一回事。
- **▶ 已做（2026-09-21，待实测）**：shader 里加了夹心 —— 新增 `TaaReinhard`（先 `max(c,0)` 再 `c/(1+c)`）与 `TaaInverseReinhard`（`clamp(c,0,0.999)` 后 `c/(1-c)`）；
  `colorC/historyC` 压到 0~1 ⇒ **AABB（含 3×3 抽头）、ClipHistory、blend 全在压缩域** ⇒ `TaaInverseReinhard(lerp(...))` 还原；
  锐化的邻域均值仍取**未压缩**的（保持原手感）；alpha 仍按原来的 `lerp` 走。**C# 一行没动**。
- **操作顺序（规划）**：
  1. **（核心，只改 shader）加 Reinhard 夹心**：`c' = c/(1+c)` 压缩 color/history ⇒ AABB / ClipHistory / blend 全在压缩域 ⇒ `r = r'/(1-r')` 还原；
     必须 `clamp`（`r'` 夹到 0.999 以下防爆、压缩前把负值夹到 0）；锐化保持在还原之后。
     验证 = 亮部（太阳/高光/天空）鬼影明显变少，中间调基本不变。
  2. （可选，先不做）历史图也改存压缩域（省一次往返、可换窄格式），但会让历史语义变化、调试更绕。
  3. （可选，先不做）真·挪位置（"其它 HDR 后处理排到 TAA 之前"）：要把 TAA 塞进 `PostFXStack`（Final → LDR 临时图 → TAA → 屏幕），
     还要处理 renderScale 的 `finalResultId/FinalRescale` 分支和分屏 viewport ⇒ 改动大、收益边缘。

### 📖 原文（`taa-张亚坤.txt`，用户 2026-09-21 拖进来）关于运动矢量的说法 —— 下一步要做的

- **位置/夹心那一段原文**："如果使用 HDR 颜色作为输入，得到的抗锯齿效果不佳。所以需要把 TAA 放到 Tonemapping 之后。但是这样又会影响后续需要 HDR 的 Bloom 等特效…
  因此我们需要先进行一次 Tonemapping，进行 TAA 后再将 Tonemapping 还原，然后处理需要 HDR 颜色输入的后处理，最终再进行一次 Tonemapping。第一次的 Tonemapping 使用比较简单的 Reinhard" ✓ = 我们刚做的 inline 夹心 ✓
- **MV 是什么**：一张 **RG16** 贴图，记录"当前帧 vs 上一帧，物体在**屏幕空间投影坐标的变化量**"（精度要求高）；**可以是延迟 GBuffer 的一部分**；除 TAA 外还能做 motion blur。
- **怎么产生**：渲染物体时要用**上一帧的投影矩阵 + 上一帧该物体的位置**（顶点同时输出"上一帧裁剪空间齐次坐标"，PS 里做差）；蒙皮物体还要**上一帧的骨骼位置**。
  **计算 MV 时不加抖动**（"为了使 Motion 的值比较精确…不会添加抖动"）。还要额外处理：UV 动画（换算到屏幕空间偏移）、**平面反射**（要推反射用的矩阵/抖动/位置，很麻烦）。
  写不了 MV 的：复杂贴图动画（粒子烟雾/水流）、半透明（MV 只有一层）⇒ 原文说一般不管（薄、消失快）。
- **怎么用（原文第 4 节，= 我们 shader 里 `TAA_MOTION_VECTORS` 那条路）**：
  `uv -= _Jitter;` → `uvLast = uv - MV.Sample(point, uv);` → `historyColor = history.Sample(linear, uvLast);`
  遮挡/去遮挡：用 **`GetClosestFragment(uv)`**（4 邻居深度取**离相机最近**的那个点去采 MV；"想要更好可以 5 点改 9 点"）—— 我们 shader 里已经原样留着（原文版比用户那份 shader 多了 `clamp(uv±k)`）。
  历史略糊：可换 **Catmull-Rom** 过滤（UE4 做法，目标点周围 5 次采样 + 权重，开销大）。
  混合系数 `saturate(0.05 + length(motion)*100)` ✓ 我们已有；最后"根据情况可选锐化" ✓ 已有。
- **效果**：动态物体（自身移动/旋转/缩放）+ 相机移动都能找对上一帧位置 ⇒ 不出鬼影/拖影；**仅重投影版对快速运动物体会出错误效果**（原文原话）。
- **落到我们管线要加什么（下一步清单）**：① 一张 MV 图（RG16，全分辨率；延迟也可挂成 GBuffer 第 5 张）；
  ② 各物体着色器加一个 **"MotionVectors" pass**（输出 `prevClip/prevClip.w - currClip/currClip.w` 的 xy），绘制时用 `PerObjectData.MotionVectors` 让 Unity 提供 `unity_MatrixPreviousM/-MI`（`Common.hlsl` 里已经 define 了 `UNITY_PREV_MATRIX_M`，说明项目本就留了这条路）；
  ③ **非抖动的** 上一帧 VP（我们现在传的 `_TAAPrevViewProj` 已经是未抖动的 ✓）；④ 相机移动是否也写进 MV：Unity 的 MV pass 会把相机运动算进去 ⇒ shader 里就**不再做深度重投影**，直接用 `uv - motion`（= 原文第 4 节）。
  ⑤ 平面反射 / 半透明 / 粒子先不管（原文也这么说）。
