## PCSS：细级联远比粗级联糊（用户实测，仅分析，未改代码）
现象：增大 `pcssSearchRadius` 时，**各"级联的模糊量变化幅度差异巨大"**——细级联远比粗级联糊。用户描述："第二个级联还相对正常，相机一靠近变成第一级联就全是模糊的一大坨"，交界处差别巨大、非常明显。
（此前"扩大正交投影腾余量 s"那版被用户第二次回退：看不出区别，且视觉上这个新问题更严重。我的判断：那版方向错——`radiusUV = min(radiusUV, maxKernelUV)` 一直在掩盖真正的问题，给 tile 腾空间只会让细级联的荒谬大核真的生效 → 更糊。）

### 根因（两条，都是"世界量 vs 每级联纹素尺度差 ~200 倍"）
按当前设置估算（maxDistance=100、tileSize=512、级联8、ratios{0.00625…0.88125}、60°/16:9）：
| | 级联0 | 级联7 |
|---|---|---|
| 球半径 R | ≈0.87 | ≈171 |
| 1 纹素世界尺寸 | 0.0034 | 0.668 |
| shader 搜索半径 | `max(0.75, 2×pcssTexelWorldMax)=1.34` 世界 | 同左 |
| 换算成该级联纹素 | **≈390 纹素（比整张 tile(512) 还大）** | **≈2 纹素** |

1. **主因**：搜索半径是全局世界值。级联 0 的搜索盘覆盖整张 tile → 必然找到邻域内任何更靠近光源的几何 → `blockerDist` 很小 → `ratio` 冲到上限 8 →
   `penumbraWS = 8×filterRadius`（=16 世界单位，而级联 0 正交框总宽才 1.74 世界）→ 整级联糊成一坨。级联 7 只扫 2 纹素 → `blockerCount≈0` → `ratio≈0` → 完全不糊。
   `pcssSearchRadius` 越大这个差距越大（细级联纹素数暴涨、粗级联几乎不变）。
2. **帮凶**：blocker bias 的保险丝 `min(biasBlockerWS, depthRange*0.05)` 中 `depthRange = R×nearPlaneOffset×20` **按级联尺寸缩放** → 该上限等价于"每级联固定 ≈51 纹素"。
   细级联需要的 bias ≈ 390 纹素×tanθ，被截掉 3~8 倍 → 平面自身邻居被判为遮挡 → 假 blocker → `ratio` 更大。
   实测对应：**级联0 被截≈8倍、级联1≈1.5倍、级联2以后不截** —— 正好匹配"第二个级联还行、第一个一大坨"。
3. 同一个"世界量发生在不同纹素尺度上"的家族问题还有：`filterRadius` 的响应速率各级联不同（1 纹素下限）、PCSS 核各向异性（标量半径 × 非正方形图集）。

### 解决方向（已告知用户，待其选择/实施）
1. **治本**：搜索半径按级联以**纹素**为单位。最省事是在 shader 加一条"该级联正交宽度百分比"上限，等价于固定纹素数：
   `searchWorld = min(_DirectionalPCSSSearchRadius, K*texelWorld)`（K 先 8~16），下限保留 2 纹素 → 各级联都只搜 [2,K] 纹素 → 假 blocker 消失、各级联模糊量趋于一致。
2. **改保险丝**：`min(biasBlockerWS, depthRange*0.05)` → 改成与 `receiverDist`（或与核半径本身）挂钩，别随级联尺寸缩放；只在 slope 估歪时兜底。
3. **治标验证**：`pcssSearchRadius` 降到 0.05~0.1（细级联纹素数下降、假 blocker 减少）——用户此前也观察到"半径很小现象几乎消失"。

### 结论性教训（给以后的自己）
- 这套 PCSS 里所有"世界单位"的半径/下限/上限，都会因为"1 纹素世界尺寸逐级联约翻倍（细↔粗差 ~200 倍）"而在各级联表现完全不同。
  凡是按"级联深度范围比例 / 世界长度"定的量，都要先问一句"换到该级联的纹素尺度上是多少"。
- 用"缩小选择球 / 扩大正交框"来给核腾空间，都只是在**掩盖**核本身过大；真正的杠杆是让核的**世界大小与级联的分辨率相称**。

## "用纹素还是用世界单位"的定论（回答用户提问，2026-09-11）
用户问：蛋白胨那篇是级联+PCSS 一起写、基于纹素做 PCSS；AKG 只写 PCSS、用世界长度。该学哪个？（用户目标：**各级联模糊程度几乎相同、搜索半径（纹素）也几乎相同**）

**结论：两个半径都要用"世界单位"，纹素只出现在"下限/参考"里。**
理由：半影（模糊）本身是世界量 → 只有用世界单位才能让各级联"看起来一样糊"。
搜索半径的职责只是"找到决定半影的遮挡物"，而该遮挡物的 texel 就在"半影宽度"以内 → 正确的搜索半径 = **ratio 上限 × filterRadius（世界）**，各级联相同。
**"搜索半径（纹素）相同" 与 "模糊相同" 互相矛盾**（除非各级联世界覆盖接近）：
- 按纹素=按 R 缩放搜索半径 ⇒ 各级联搜的**世界邻域差 200 倍** ⇒ 粗级联搜到大邻域、细级联搜不到真遮挡物 ⇒ **粗级联反而更糊**。
- 你的 8 级联跨度 0.6m~100m（200:1），只能选世界制。蛋白胨那套能"绑纹素"的前提是级联世界覆盖接近（级联少/每级联单独贴图），搬到大跨度上会变形。

**数学上的一句话根因**：需要的 bias = 搜索盘跨过的地形起伏 = **世界搜索半径 × tanθ（与 R 无关）**；而保险丝 `cap = depthRange×0.05 ∝ R`。
⇒ 比值 需求/cap ∝ 1/R → **细级联被截**（级联0 ≈8倍、级联1 ≈1.5倍、级联2+ 不截）→ 平面自身邻居被判为遮挡 → 假 blocker → ratio↑ → 糊；搜索半径越大需求越大 → 越糊 ✓ 完全对应观测。
反过来，若搜索半径 = N 纹素（∝R），则需求/cap = 10·N·tanθ/tileSize，**与级联无关** → 各级联一致（这是纹素制唯一的优点），但代价是模糊不一致（粗级联更糊）。

### 建议的修法（待用户确认，改 2 处 shader + 1 处 C# + 参数）
1. **修 bias 保险丝（关键）**：`min(biasBlockerWS, depthRange*0.05)` 中的 `depthRange` ∝ R 是罪魁 → 换成与级联尺寸无关的量（如 `receiverDist*0.5`）或把系数提到 0.5 量级，让它只在 slope 估歪时兜底、日常不生效。
2. **搜索半径上下限都用世界量**：下限改成"**该级联自己的** 2 纹素" `2*texelWorld_i`（现在错在用最粗级联的 2 纹素 → 细级联下限 = 390 纹素！），上限 = `ratioCap*filterRadius`（= 最大可能半影，再大也没意义、只增加假 blocker 风险）。
3. **参数回归合理尺度**：`filterRadius` 2 → 0.1~0.3（否则最大半影 16 世界 ≫ 级联0 覆盖 1.7 世界，必然"一大坨"）；`pcssSearchRadius` 0.75 → 0.1~0.2。可选护栏：`penumbraWS = min(ratio*filterRadius, 0.25*R_i)` 防止细级联被整片糊掉。
4. 已告知用户：我之前提的"按级联正宽百分比给搜索半径加上限（=固定纹素数）"只对一半 —— 它能消假 blocker，但会把系统变成"纹素制"从而破坏模糊一致性；**应采用上面第 1+2 条的世界制方案**。

磁盘现状（本次实读，与上面第 66 条的记录不同）：`ShadowSettings.Directional` 现在是
`pcssSearchAnchorTexels`(int,[4,64]，≤0视默认20) + **`pcssFilterTexels`**(int,[2,64])，`pcssFilterRadius`/`pcssSearchRadius` 已不存在；

`ratio = saturate((receiverDist-blockerDist)/_DirectionalPCSSPenumbraRef)`，
`penumbraTexels = ratio*_DirectionalPCSSFilterTexels*hitFade`，`radiusUV = pow(penumbraTexels,pow)*_ShadowAtlasSize.y`；
`searchWorld = max(_DirectionalPCSSSearchRadius, 2.0*texelWorld)`；bias 无 ∝R 的 cap，PCF 侧 cap = `receiverDist*0.5`。

用户新报问题："远糊近清"（细/近级联清晰、粗/远级联糊；但同一条消息开头又说"近处非常模糊、远处非常清晰"，方向互相矛盾，待实测确认）。

### 蛋白胨原文（用户提供）关键代码与读法
- `blockerSearchWidth = 20 * OrthHalfWidth0/OrthHalfWidth`，用在 `shadowCacheId + offset*searchWidth`，
  而 `shadowCacheId = shadowCoord.xy * (_ShadowmapCacheSize.xy-1)` 是**像素/纹素坐标** ⇒ 该值是"**本級联的纹素数**"，
  换算回世界恒等于常数 = cascade0 的 20 个纹素 ⇒ **世界制**（不是纹素制）。64 点泊松盘，每级联同一物理邻域。
- 半影：`banying = |mDepthLS - blockerDepthLS| * _CascadeZDistanceArray[cascadeIndex] / OrthHalfWidth;`
  `banying = min(banying*10, 100/OrthHalfWidth);` 之后当作 **像素/纹素半径**用（`shadowCacheId + offset*filterWidth`）。
  ⇒ 结构上 = `min(k * Δ世界深度, C) / OH`：**世界半影恒定**（分母 OH 只是把世界长度换算成 tile 比例），
  上限也是同一种换算（"最多占 tile 固定比例"），**没有 ∝R 的硬截断**。
- bias：`tan = lightDir.y/sqrt(1-lightDir.y²)`；`texelSize = OH/512`；
  `deltaZ_WS = 核半径(纹素) * texelSize / tan` → `deltaZ_LS = deltaZ_WS / CascadeZDistance`。
  即"深度偏移 = 核跨过的地形起伏"，blocker 与 PCF 两处都加；不这么做会有"高物体阴影边缘突变"（PCF 核过大 + ddx/ddy 不可用）。
- 之后还有：屏幕空间 SSShadowmap（compute shader）+ 9 点邻域早退（全内/全外直接出结果）+ 龙书双边模糊去噪。

### 给用户的结论（简单说）
1. 规则：**半径的世界大小必须与级联无关，级联量只能出现在"换算"里（世界→UV/纹素）**。
2. 用户代码主因：`radiusUV = penumbraTexels * _ShadowAtlasSize.y` 把半影做成了"本級联纹素个数" ⇒
   世界半影 = N×texelWorld_i，粗细级联差 ~200 倍 ⇒ 必然一头糊一头清。改法同文章：`penumbraWS = ratio*世界最大半影`，
   `radiusUV = penumbraWS * worldToUV`（别再乘纹素个数）。
3. 次因：`searchWorld = max(锚点, 2*texelWorld)` 的下限 ∝R，对粗级联会反超锚点 ⇒ 粗级联搜到大世界邻域 ⇒ 更糊。
   下限改成"占正交宽度的比例"或去掉。
4. 取舍：8 级 200:1 跨度下"搜索半径纹素数一致"与"世界模糊一致"**不可同时成立**，优先保世界模糊一致。

## 用户提供蛋白胨完整代码后的定论 + 修正实现（2026-09-11 后半）
**蛋白胨代码读出来的三件事（权威）**：
1. **搜索半径 = 固定世界长度**：`blockerSearchWidth = 20*OrthHalfWidth0/OrthHalfWidth` 是**像素/纹素**单位（用在 `shadowCacheId + offset*searchWidth`），乘回本級联纹素世界尺寸 = `20*R_0/R_i * (2R_i/512)` = **常量 = cascade0 的 20 个纹素宽** ✓
   → 所以"各级联搜同一块物理邻域"。同理他的 bias `deltaZ_WS = blockerSearchWidth*texelSize/tan` 也是**与世界固定**的 ✓
2. **半影 = (世界深度差 Δd) / 本級联球半径 R_i，然后直接当 shadowmap 的"像素半径"用**（`offset*banying`）→ **半影用纹素/像素计** ✓ → 这才是"各级联看起来一致"的原因。
3. 大核下还要按 `半影纹素 × 本級联纹素世界尺寸 / tanθ` 修正 depth bias（我们已有等价形式）；最后是屏幕空间 shadowmap + 双边模糊去噪（另一摊）。

**我上一版（把搜索半径做成"本級联 16 纹素"）错在哪 → 用户看到的"近处锐利、远处非常模糊"**：
- 搜索半径换到世界：细级联 16×0.0034 = 0.054 世界、粗级联 16×0.668 = 10.7 世界 → **粗级联搜的世界范围大 200 倍 → 到处都能找到 blocker → 远处全糊**；细级联只搜 5cm → 基本找不到 → 近处锐利 ✓ 完全对应观测。
- 另外我把 Δd 除以"搜索半径"（很小）→ 一有遮挡物就饱和到最大模糊，加剧了它。
- **教训：搜索半径必须是世界固定（锚最细级联）**，只有**半影**才用纹素制。

**当前实现（已改好，是"世界固定搜索 + 纹素制半影 + 世界参考归一化"的组合）**：
- `ShadowSettings`：`pcssSearchAnchorTexels`（默认20，搜索半径锚点=最细级联的N个纹素）+ `pcssFilterTexels`（默认20，半影上限的纹素个数）。
- `Shadows.cs`：`PCSSSearchRadiusWorld = anchorTexels * pcssTexelWorld0`；`PCSSFilterTexels = clamp(设置,2,64)`；`PCSSPenumbraRefWorld = pcssSphereR0`；
  上传 `_DirectionalPCSSSearchRadius` / `_DirectionalPCSSPenumbraRef` / `_DirectionalPCSSFilterTexels`；`RefreshPCSSRadiusMetrics()` 仍在 `Render()` 最前面。
- `Shadows.hlsl`：`searchWorld = max(_DirectionalPCSSSearchRadius, 2*texelWorld)`（世界固定+每级联2纹素下限）；
  `ratio = saturate(Δd / _DirectionalPCSSPenumbraRef)`（世界参考，与级联无关）；
  `penumbraTexels = ratio * _DirectionalPCSSFilterTexels * hitFade`；`radiusUV = penumbraTexels * _ShadowAtlasSize.y`（纹素→uv）；
  `penumbraWS = penumbraTexels * texelWorld`（给 bias 用）；blocker 的 bias 不 clamp；PCF 的 cap = `receiverDist*0.5`。
- 修正此前记忆里的一句：**不能笼统说"蛋白胨不是纹素制"——他的搜索半径是世界固定，但半影确实是纹素/像素制**。
- 固有极限（已告知用户）：8 级联 200:1 时，粗级联的 shadowmap 里可能根本没有那个遮挡物（超出其正交框深度范围）→ 再怎么改公式也消不掉这部分差异；要彻底一致只能减少级联数/调整比例，或上屏幕空间方案。

## 用户实测：开关 PCSS 会让阴影"朝一个方向移动"（诊断，未改，2026-09-11）

1. **法线偏移**（`Shadows.hlsl` L324-326）：
   - PCF：`shadowNormalBias(Unity Light 默认1) × filterSize × 1.414`，PCF2x2 时 `filterSize=1×texel` → ≈ **1.414 纹素**，**与入射角无关**。

2. **深度偏移**（`Shadows.hlsl` L222 `biasBlockerWS` / L257 `biasPCFWS`）：PCSS 额外加 `(texelWorld + searchWorld) × slope × pcssSlopeBias(0.6)`（PCF 阶段那行还把 `penumbraWS` 加进去）；
   PCF 路径**没有**接收端世界空间深度偏移（只有投射端 `SetGlobalDepthBias(0, light.shadowBias)`，Unity 默认 0.05）。
   注意 `searchWorld` 被乘进 bias → **调 `searchTexels` 也会推动阴影边缘**（"半径只影响模糊"这个直觉在现在的公式下不成立）。
3. **快速验证**：`pcssNormalBias=0` + `pcssSlopeBias=0` → 开关 PCSS 位移应基本消失（只剩对称变糊）。
4. **对齐方案**：① `PCSSNormalBiasOffset` 去掉 `(1-nl)`、乘 `1.4142`，再把 `pcssNormalBias` 设成主光 `Shadow Normal Bias` → 与 PCF2x2 完全等价；

## 用户实测：PCSS 有时比纯 PCF 还硬/不自然（分析，未改，2026-09-11）
**核心区别：PCF 的"软"是无条件的（每级联固定 (filter+1) 纹素 tent + 硬件线性比较采样），PCSS 的"软"是有条件的（半径 ∝ 世界深度差，且走 point 采样）。** 四条原因：
1. **半径会掉到 0，而 PCSS 用 point 采样（主因）**：`SamplePCSSDepth` = `sampler_point_clamp`，没有硬件双线性；`ratio = saturate(Δd/_DirectionalPCSSPenumbraRef≈1.26m)` 在日常场景（矮遮挡、小间隙）很小 → `radiusUV→0` → 16 个样本全落同一纹素 → **纯二值硬边，比 PCF2x2 还硬**（PCF2x2 至少有 2x2 亚纹素渐变）。L253 那行"至少1纹素"的下限目前是**注释掉的**。
2. **世界固定半影 × 粗级联 = 亚纹素**：`PenumbraMaxWorld ≈ 0.1m` 是常量，粗级联 1 纹素已达 0.6m → 半影表达不出来；PCF 则每级联都糊 (filter+1) 纹素 → 这就是"分辨率不够时 PCSS 反而不如 PCF"，是"世界一致"的必然代价（早前已记录）。
3. **泊松盘根本没旋转（真 bug）**：`GetPCSSRotation` 算了 `rotAngle` 却 `return float2(0.0, 1.0)`（L272-288）→ 全屏同一套 16 点图案 → 结构化重复 + 噪声，观感"毛/硬/不自然"；PCF 的 tent 是加权平滑，没这问题。
4. `hitFade` 命中比例低时再打折半径 → 浅场景更偏硬。

## 蛋白胨的 ddx/ddy 深度偏移 vs 我们的实现（2026-09-11）

- **ddx/ddy 的作用是算深度偏移（消除高物体阴影边缘的台阶），不是"让边缘变模糊"**（模糊靠核半径）。

## 第 3 步（屏幕空间 PCSS）方案澄清（2026-09-11，只解释未动手）

  pass0 `Name "PCSS"`、pass1 `Name "Blur Horizontal"`、pass2 `Name "Blur Vertical"`（仍空）。
- **pass0**：抄 `DeferredLightPassFragment` 的深度重建（`mul(UNITY_MATRIX_I_VP, posClip)` + `UNITY_UV_STARTS_AT_TOP` 翻 y）+ 读 `_GBuffer2` 法线 → 伪造 `Surface`
  （只填 position/depth/dither/interpolatedNormal + 中立值）→ `GetShadowData` → `GetDirectionalShadowData(0, ...)` → **`GetCascadedShadow`** 输出。
  - **输出口径 = 纯实时阴影**（不含 `MixBakedAndRealtimeShadows`、不含 `strength` 衰减）→ 下一步光照Pass只需把 `GetCascadedShadow(directional, global, surfaceWS)` 这一句换成采样本图，其余分支不动。
  - **故意不走 `GetDirectionalShadowAttenuation`**：它开头 `#if !defined(_RECEIVE_SHADOWS) return 1.0`，而 `_RECEIVE_SHADOWS` 是材质关键字、全屏材质外可能没开（Runtime 里确实没人全局 EnableKeyword("_RECEIVE_SHADOWS")）→ 会整块白算。**待确认：deferred 光照Pass现在是否真拿到阴影。**
  - 关键字只声明 `_DIRECTIONAL_PCSS` + `_SHADOW_PCF3/5/7`（8 变体）。
  - `surfaceWS.depth` 用 `-TransformWorldToView(pos).z`（米），**不要**学 `DeferredLightPassFragment` 的 `surface.depth = GTDepth`（原始深度，对 `FadedShadowStrength` 是错的）——已在回复里提醒用户。
- **pass1**：5 抽头二项式核 (1,4,6,4,1)/16 横向，`texelX = _CameraBufferSize.x`（**改半分辨率时要 ×2**），读 `_ScreenSpaceShadowTex` 写 `_ScreenSpaceShadowTex_TempBlur`；目前**没有**做深度双边权重（跨物体边缘可能轻微漏阴影，可后加）。
- pass2（纵向）未实现；shader 仍未被任何 C# 引用（无材质、无绘制调用）。
