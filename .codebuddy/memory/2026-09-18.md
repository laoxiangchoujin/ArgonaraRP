## Hi-Z：毅毅文章的全流程（解释给用户，未动代码）

用户问"毅毅的代码流程是怎样的 + 我该不该专门开一个脚本"。回答要点如下。

**两个文件**：`HiZRenderFeature.cs`（Feature + Pass，生成 Hi-Z）+ `HiZShader.shader`（一趟"4 取 max"的降采样）。

**生成流程**（每帧）：
1. `Feature.Create()`：建 pass、建 material、预分配 RTHandle —— 主图 `_HiZTex`（带 mip 链）+ 每级一张单 mip 临时图 `_HiZTex0..5`（中转用，因为"直接渲染到主图某一 mip"在 Blitter/RTHandles 路径下不生效）；同时拿到 `_HiZSourceMipLevel` / `_HiZDestinationMipLevel` / `_HiZMipLevelSize` / `_MaxHiZMipLevel` 的 id。
2. `AddRenderPasses` 入队；`SetupRenderPasses`（URP 钩子）把 Inspector 的 settings 传给 pass。
3. `OnCameraSetup`：取相机深度图 → 按 `2^ceil(log2(W)-1)` 定 mip0 尺寸 → 主图描述符（`R32_SFloat`、useMipMap、mipCount、sRGB=false、msaa=1）→ `ReAllocateIfNeeded` 分配 → 循环分配每级临时图（每次宽高减半、最小 1）。
4. `Execute`：`Blit(深度图 → HiZ[0])` → `CopyTexture(HiZ[0] → 主图 mip0)`；`for i=1..mipCount-1`：设三个 uniform（源/目标 mip、源级尺寸）→ `Blit(HiZ[i-1] → HiZ[i], material, 0)` → `CopyTexture(HiZ[i] → 主图 mip i)`；最后设 `_MaxHiZMipLevel = mipCount-1` + `SetGlobalTexture(_HiZTex, 主图)`。
5. shader：全屏，取 4 个对角邻居（±1 纹素 × (1/w,1/h)）的深度取 **max**（ReverseZ ⇒ max = 该块最近的表面）。
6. 使用（trace）：射线截断到近平面 + 法线偏移 → 转屏幕、选主轴做 DDA（求 dPosSS/dInvW × stride）→ 循环里 `+= dPosSS * 2^mip`（**mip 决定步长**）→ 算两端视深度 → 采 `_HiZTex` 当前 mip → `LinearEyeDepth` → `rayFarZ <= surfaceZ` 则可疑：mip0 时用 thickness 判命中，否则回退一步 + `mip--`；安全则 `mip = min(mip+1, max)`；出屏幕 return false。
7. `Dispose`：所有 RTHandle `Release()` + `CoreUtils.Destroy(material)`。

**给我们项目的落地建议**：**要专门开脚本**，但按自定义 SRP 的风格写 —— `Runtime/HiZ.cs`（普通类，像 `ScreenSpaceReflection.cs`：`Build(buffer, 深度图, w, h)` / `Dispose()`，内部用 `GetTemporaryRT(useMipMap:true)` 一帧建一帧放）+ `Shaders/HiZ.shader`（1 个降采样 pass）；**先由 `ScreenSpaceReflection` 内部持有一个实例**（目前唯一消费者），等 SSAO/其它也要用时再提到渲染器层共享。理由：Hi-Z 与 SSR 是两件事（可复用）、自成一套 RT/尺寸/mip 逻辑、且与项目"一个功能一个类 + 一个 shader"的风格一致。可选：直接 `SetRenderTarget(rt, mipLevel, CubemapFace.Unknown)` 渲染进 mip，省掉每级的临时 RT + CopyTexture。

## 补充（用户追问"生成 Hi-Z 的细节"）

- **尺寸公式的真实结果**：`2^ceil(log2(W)-1)` 得到的是"**小于 W 的最大 2 的幂**"（1920→1024、1080→1024）⇒ 1920×1080 屏幕上**恰好凑成 1024×1024 的方形**（用户印象里的"正方形纹理"就是这么来的，是巧合，不是设计）。它比屏幕小 ⇒ mip0 已经是一次降采样，所以第一步是 **blit（重采样）** 而不是 1:1 copy。要 2 的幂是为了每级整齐减半；**现代做法不必**，每级 `max(w/2,1)` 即可（用 point 采样 + ±0.5 纹素偏移，奇偶尺寸无所谓）。
- **为什么要采 4 个"对角"邻居**：父像素 = 上一级 **2×2 个纹素**，只有采左上/右上/左下/右下才"不重不漏"（就是四叉树父 ← 4 子取 max）。采上下左右会**漏掉本块内的像素**并把邻块的值混进来。偏移量：目标像素中心 → 4 个源纹素中心 = **±0.5 源纹素**（配 point 采样）。文章写的 ±1 纹素 + **线性采样** ⇒ 每个采样点落在纹素交界 ⇒ 实际是"4 个平均的 max" = 把 max 抹平（存进去的值**比真实最近表面更远**）⇒ 判定"安全"过频 ⇒ **漏交**（这是我把"改成 point + ±0.5"列为必改的原因）。
- **两个易混点（用户再次追问后澄清）**：① "直接画进 mip" 省掉的是**临时中转图**（N 张 → 0 张），**mip0 永远存在**（mip 链的第 0 级；尺寸与深度图一致就直接 copy、不一致才 blit 一次）—— 不是"连 HiZ0 都不要"。② **"2 的幂/方形"与"要不要临时图"是两件独立的事**：2 的幂只是让每级整齐减半、省心，**不是数学必需**（降采样是我们自己写的：目标像素中心对应源 2×2 的中心 ⇒ point + ±0.5 纹素，奇偶尺寸都行）；2 的幂的代价是 mip0 比深度图糊（1920→1024）。
- **"为什么是 4 个对角"的正解（图示法）**：上一级 4×4 → 这一级 2×2；目标的**左上**像素覆盖的正好是源的 `a b / e f` 这一块 2×2 ⇒ 它的 4 个"孩子"在源图上就是相对该块中心的左上/右上/左下/右下 ⇒ 取 max 写进目标左上像素。**采哪几个由覆盖关系决定，不是随便挑**。采"上下左右"会横跨两个目标像素 ⇒ 每块漏掉自己的一部分、又混进邻居的一部分。
- **mip0 的落地细节**：不做 2 的幂 ⇒ 主图 mip0 尺寸与深度图一致，但仍**不能用 `CopyTexture` 直接拷**（深度附件是深度格式，目标是 `R32_SFloat`，跨格式拷贝不支持）⇒ mip0 也要一趟全屏 blit（1:1、无损）。采样时 ±0.5 纹素用的是**源级**（上一级）的纹素尺寸 ✓（文章传 `_HiZMipLevelSize` = 源级尺寸，这点是对的；错的只有采样器用了线性、偏移用了 ±1）。

## 实测结论：直接画进 mip 走不通（2026-09-18）+ 加了 DontCare

- **实测（用户用 RenderDoc/FD 看）**：`_HiZTex` **只有 mip0 有数据，mip1..mip10 全黑** ⇒ 判据命中：**"同一张图既当 SRV 又当 RTV"在 D3D 下不成立**（采 `_HiZTex` 得到 0 ⇒ `max(0,0,0,0)=0`）⇒ **"直接渲染进主图 mip"这条路否掉**，需退回"每级临时图 + `CopyTexture`"。
- **"为什么 6 级却看到 mip0..10"**：`useMipMap = true` 建的是**完整 mip 链**（1920×1080 ⇒ `floor(log2(1920))+1 = 11` 级，索引 0..10）；我们只写 `mipCount` 级（6），其余从没写过 ⇒ 黑/垃圾，且被 `_MaxHiZMipLevel = 5` 挡住不会采到。**正常现象**。
- **已加 DontCare/Store**：`Draw` 里改用 `new RenderTargetIdentifier(hiZTexture, i, CubemapFace.Unknown, 0)` + `SetRenderTarget(id, RenderBufferLoadAction.DontCare, RenderBufferStoreAction.Store)`（**没有**"带 mipLevel 又能带 action"的重载，所以要这么拼）。整屏覆盖 ⇒ Load 可省；结果后面要读 ⇒ Store 必须留。
- **下一步（退回方案，只改 C#）**：每级用 `GetTemporaryRT(_HiZTemp + i, w>>i, h>>i, 0, Point, RFloat)` 建 N 张**单级**临时图；`Mip0` 那趟画进 temp0 再 `CopyTexture(temp0 → 主图 mip0)`；循环 i：把 temp[i-1] 当 `_HiZTex` 绑（`_HiZSourceMipLevel = 0`）→ 画进 temp[i] → `CopyTexture(temp[i] → 主图 mip i)`；循环后把 `_HiZTex` 绑回主图给追踪；`Draw` 末尾 `ReleaseTemporaryRT`（不用 `Cleanup`）。**shader 一行不用改**。临时图 id 可照 `PostFXStack` 的 bloom 金字塔写法（`Shader.PropertyToID("_HiZTemp" + i)` 连续分配）。

## 定案：改成"每级临时图 + CopyTexture 进主图"（2026-09-18，用户批准方向，仅给了方案未动代码）

用户问三件事，结论：
1. **要 temp0**（不建议省）。省掉它 = "mip0 那趟直接写主图 mip0"，而主图在上一帧末尾被绑成了 `_HiZTex`（给追踪用）⇒ 又踩回"同一资源既绑 SRV 又当 RTV"。保留 temp0 之后规则极简：**生成阶段完全不碰主图（全在临时图上算），主图只负责最后收 `CopyTexture` 和被绑给追踪**。代价：多一张全分辨率 RFloat 临时图（走 RT 池，不常驻）。
2. **每级都要一张**（尺寸各不相同，源/目标不能同一张）⇒ 从 temp0 到 temp(N-1) 共 N 张。

## Hi-Z trace 跑通 + 高 mip 反射残缺的原因（2026-09-18，只分析未改）

用户反馈：Hi-Z 版和线性版"挺像"、有反射、**基本没看到自交**；但把 Hi-Z 的 mip 级数调高（≥4 级）后**图像被截断/反射不完整**。

**对齐情况**：坐标系（屏幕空间 + 1/z 插值）、深度口径（视空间米、正值）、jitter 表、`_SSRPixelStride`/`_SSRNearStepBoldenRange`/`_SSRPixelThickness` 的语义、以及命中后的全部处理（背面剔除 / `alphaCalc` / 粗糙度取 mip）**都已对齐/共用**。刻意不同的：① 循环次数（线性版=按屏幕跨度算出的 stepCount；Hi-Z=固定 `_SSRStepCountLimit`）；② **没有末尾二分** ⇒ 命中精度只到 mip0 一个纹素；③ `marchPercent` 用 1/z 参数（比线性版的"按步数"更准）；④ 采样点是"这一步的终点"（线性版取起点像素）⇒ 命中点整体略偏后；⑤ 无线性版的 0.1 步自交推送。

**高 mip ⇒ 反射残缺的原因（主因 + 次因）**：
- **主因**：步长 = `stride × 2^mip` 像素，但只采样了终点所在的那个 mip 级纹素（覆盖 `2^mip` 像素）⇒ **一步的中间大部分区域根本没被检查** ⇒ 漏交（反射残缺/断带），mip 越高越严重。
- **次因**：一步跨出屏幕就 `return false`（和线性版一样），大 mip 一步就冲出去 ⇒ 射线提前结束。
- **解法（按性价比）**：① 级数别调高，5~6 级足够（mip5 一个纹素已覆盖 32×32 像素）；② `_SSRPixelStride` 调到 ~1 ⇒ "一步" = 当前级一个纹素的跨度，步长与覆盖 1:1 对齐（起步阶段步数变多，但 mip 很快升上去）；③ 越界时先降 mip（`if (mipLevel > 0.5) { mipLevel -= 1.0; continue; }`）再 return false；④ trace 侧再 clamp mip 上限（如 min(_,4)）。
- **"参数要比线性版宽松"的含义**：Hi-Z 一步可能宽 `2^mip` 倍，用线性版的 thickness 容易"该命中没命中"（断带）⇒ 文章把 stride/thickness 加大。我们基准步长沿用线性版 ⇒ **先不用专门调**；真要更严肃可把厚度按步长缩放（`_SSRPixelThickness * stepScale`），留待以后。

## 复查续：stride=1、mipCount=5 仍"截断"的定位（2026-09-18，只分析未改）

用户实测 `mipCount = 5`、`_SSRPixelStride = 1`、步数上限 128 **仍有截断** ⇒ 说明主因不是"步长 vs 覆盖"的缺口（stride=1 时二者 1:1 对齐 ✓），而是：
1. **命中判据太严（主因）**：我们写的是 `abs(surfaceZ - rayNearZ) < _SSRPixelThickness` —— 只认"表面离**这一步的起点**很近"。但 Hi-Z 的一步在深度上的跨度是线性版的 `2^mip` 倍，表面落在这一步**中间**时，`rayFarZ > surfaceZ` 成立（可疑）、却过不了那个 abs 判据 ⇒ **漏交**。⇒ **改成和线性版 `intersect` 同口径**：`surfaceZ < rayFarZ && surfaceZ > rayNearZ - _SSRPixelThickness`（表面落在这一步的深度范围内）⇒ 大 mip 的长步也不会漏。
2. **越界直接 `return false`（次因）**：mip 大时"第一步就跨出屏幕"很常见（尤其掠射反射），此时射线被放弃 ⇒ 边缘处该有的反射消失（观感=截断）。⇒ **改成先降级**：`if (out) { if (mipLevel > 0.5) { mipLevel -= 1.0; continue; } return false; }`（一步太大就缩回来用更小的步重试，只有 mip0 还越界才算真出屏）。
3. 可选：trace 侧再 clamp mip 上限（如 `min(_MaxHiZMipLevel, 4)`）。

**答复用户的"mip 越高步长越大 ⇒ 跨越"**：对，但**变大本身是设计如此**（这正是它快的原因）；错在"判交/越界这两处没跟上'这一步可能很长'这个事实"。

## 已实施 A + B（2026-09-18，`ScreenSpaceReflection.hlsl` 的 `traceRayWithHiZ`）

## 正解："基准步长封顶（可达距离）+ 采样级抬高 log2(基准步长)（对齐覆盖）"（2026-09-18，已改）

**两头矛盾的真正解法**（两者并不冲突，只要把"步进级"和"采样级"分开）：

- **采样级抬高 `mipOffset = log2(basePixels)`**：步长 = `basePixels × 2^mipLevel` 像素，而抬到 `mipLevel + log2(basePixels)` 的那一级，其纹素覆盖正好 = `basePixels × 2^mipLevel` ⇒ **步长与被检查的覆盖重新 1:1 对齐、不漏**；
- 步进级上限随之降为 `maxStepMip = _MaxHiZMipLevel - mipOffset`（否则步长会超出该级覆盖）。

代码：`basePixels = max(screenSpan / baseStepCount, 1)`、`mipOffset = max(log2(basePixels), 0)`、`maxStepMip`；循环里 `sampleMip = min(mipLevel + mipOffset, _MaxHiZMipLevel)` 用于采样，`mipLevel = min(mipLevel + 1, maxStepMip)` 用于升档。之前"封顶⇒漏 / 不封顶⇒走不远"的来回，就是因为没把这两件事分开。

2. **`stride` 这类"人为拉长步长"的旋钮是干扰吗？** —— 是。步长必须 = 格子尺寸，任何人为放大都破坏它；`stride > 1` 只能靠 `thickness` 补（毅毅的做法，他自己承认要反复调参）。**我们项目里"按跨度封顶拉长"是最大的干扰源**。
3. **具体怎么动（只在 Hi-Z 版，不动线性版）**：① 去掉 `baseStepCount` 的封顶 ⇒ 基准步长 = `pixelsPerStep`（`stride=1` 时 1 像素）、不再随跨度变；② 用 `_SSRStepCountLimit` 当唯一的上限（必要时调大）；③ 保留已有的"越过射线终点就停"；④ `mipCount` 5~6 作为"多远"的主旋钮；⑤ 注释写明 `stride > 1` 需要 thickness 补。

## 澄清"改动量"（2026-09-18，未改）

用户以为"让步长 = 1×2^mip 像素"会接近重写 `traceRayWithHiZ`。**实际只需要去掉 `baseStepCount` 的那个 `min(_SSRStepCountLimit, …)` 封顶**（≈一行）—— 因为函数骨架早就是 Hi-Z 的样子（屏幕空间参数化、升降 mip、终点判据、近平面截断、厚度确认都在），唯一"错"的就是步长被人为拉长。
两个小提醒：① `stride = 1` 时基准步长其实是 **1~2 像素**（`_SSRNearStepBoldenRange` 的近处放宽项会把它顶到 ×2）；要严格 1 像素得把这一项去掉或把范围设得极大（可选，1~2 倍偏差两篇文章里也存在）。② 去掉封顶后密几何区域走得慢 ⇒ 大概率要把 `_SSRStepCountLimit` 调大（参数，不改代码）。

+ int baseStepCount = max((int)ceil(screenSpan / pixelsPerStep), 1);                            // 现在：≈ 1~2 像素（stride=1）

### 补覆盖的三种做法（同一目标，别混）

## 逐字复核毅毅文章的 trace 代码，与我们 `traceRayWithHiZ` 的差异（2026-09-18，用户要求"找问题"）

毅毅的 HiZRayMarching 关键点（真码，不是伪码）：
- **起点沿法线偏置**：`rayVS = posVS + normalVS * rayOffset`，该偏置**只用来给首步的 `preZ`**（后面每步 `preZ = rayFarZ` 就自动丢掉偏置）⇒ 只影响起点那一小步，不影响后续。
- **步长 = 沿"主轴"1 像素 × stride**（先交换 xy 让 x 是主轴：`dPosSS = float2(dir, invdx*Δy)` 再 `*= stride`；`dInvW` 同理）⇒ stride ≥ 1 时**主轴每步走 stride 像素**，格子只有 2^mip ⇒ **他们采样同样盖不满一步**，靠**大 thickness** 兜（文章原话："Stride 和 Thickness 都要比线性版取大得多，否则出现非常严重的断层"；"太大就会走样"）。
- **采样点 = 逐步后的新位置**（currPosSS），命中位置直接就是它（**没有终点二分**）；`rayFarZ` 用 `-1/(currInvW + dInvW*2^mip*0.5)`（采样点**再**半格）。
- **命中判据（mip0）= 双边窗口**：`abs(surfaceZ - rayNearZ) < thickness` —— 面落在射线深度 ±厚度 内即算命中，**不要求"射线已越过面"**。
- 可疑且 mip>0：**显式回退一步**（`currPosSS -= dPosSS*2^mip; currInvW -= ...; preZ = -1/currInvW; mipLevel--`）—— 与我们的 `continue`（不推进）等价。
- **循环以"主轴坐标越过终点"结束**（`currPosSS.x*dir <= end`）：不夹步长、不早退。出屏直接 `return false`（不降档）。

我们与之的实质差异（按"可能还在漏内容"排序）：
1. **命中窗口：他们双边、我们单边**。我们要求"射线已越过面"（`sampleZ > surfaceZ`）⇒ 窗口只有他们的一半，"擦过去、面还在前方一点点"那类会漏。
2. **厚度量级**：他们靠**大厚度**兜漏交；我们用线性版那套小厚度（0.15m）⇒ 更容易漏。**零成本验证：厚度 0.15→0.5~1.0 再试**（上次试早于自交带/1px 步的改动）。
3. **起点保护**：他按法线偏置一步；我们 `inSelfBand`（深度离起点 ≤ 厚度**整段**当空）⇒ 深度几乎不变的射线（平行视平面）整条被当空、永远没反射。
4. 小差异：我们出屏先降档重试（最多白吃 `_MaxHiZMipLevel` 轮），他们直接 return false。我们比他多的：中点采样（他们采步子末端）、`atRayEnd` 夹步长（夹后那一步 ≤ 一格，所以被采的格子仍盖得住这段，问题不大）。

## 中点采样补充修正：判据锚点必须跟着采样点（2026-09-18，已改，待测）

**判据口诀（写下来的经验）**：**采样点在哪，判据就得锚在哪**。采样点搬到中点而判据仍锚在步子远端 ⇒ 假命中（提前半步）；判据锚在中点而漏了"这一步的后半" ⇒ 漏交。两者必须一致，否则要么多白点、要么漏。若这版仍不对，下一手就是**整体回退到端点采样**（一致但那套会漏边缘），再换"步长 = 半格"（`stepScale = exp2(mipLevel-1)`，保守、只会多降档）去补覆盖。

## 找到根因：Hi-Z 步进采的是"步子末端"，漏掉每步前半格（2026-09-18，已修）

用户复核 Hi-Z 各级贴图：**值确实是 max（越往上越近），数据没问题** ⇒ 排除纹理侧。回到 trace，锁定唯一自洽的解释：

**`traceRayWithHiZ` 原来采的是 `nextSS`（这一步的末端）**。而这一步跨 `base × 2^mip` 像素，其中 `2^mip` 正好是当前级一格的宽 ⇒ 落在末端的那个格子只覆盖 `[末 − 半格, 末 + 半格]` ⇒ **这一步的前半格（≥2^(mip-1) 像素）从头到尾没被采样过**，而且下一步从末端接着走、永远补不回来 ⇒ 每步恒定漏掉约一半路程；mip 越高漏掉的越长（mip4=8px、mip5=16px）⇒ 树冠/叶片这种细几何正好躲进去 ⇒ 全程判 "safe" ⇒ 一路升 mip 跳到尽头也不命中 ⇒ **黄**。

**已修（`ScreenSpaceReflection.hlsl` traceRayWithHiZ）**：新增 `sampleSS = currentSS + deltaSS * (0.5 * stepScale)`，采样、`hitPixel`、`marchPercent`（用 `current1bz + 0.5*delta1bz*stepScale`）全改成用中点；步进的 `currentSS/current1bz` 仍推进到 `nextSS/next1bz`。
**若还漏**：下一步的杠杆是让"一步 = 正好一格" —— 基准步长压到 1 像素（`_SSRPixelStride` 调小、近处别放大），或改 `stepScale = exp2(max(mipLevel-1,0))`（每格采两次）。

## 已应用方案 A（2026-09-18，后已回退）

`ScreenSpaceReflection.hlsl` 的 `traceRayWithHiZ`：
```hlsl
float stepPixels = max(min(screenSpan / (float)baseStepCount, (float)(1 << _MaxHiZMipLevel)), 1.0);
float stepRatio  = stepPixels / screenSpan;          // 每步占整条射线的比例
float2 deltaSS   = (endSS - startSS) * stepRatio;    // （delta1bz 同理用 stepRatio）
int   mipOffset  = (int)ceil(log2(max(stepPixels, 1.0)));
float maxStepMip = max((float)(_MaxHiZMipLevel - mipOffset), 0.0);
...
float sampleMip = min(mipLevel + mipOffset, (float)_MaxHiZMipLevel);   // 采样级抬高
rawHiZ = SAMPLE_TEXTURE2D_LOD(_HiZTex, sampler_point_clamp, nextSS, sampleMip).r;
...
mipLevel = min(mipLevel + 1.0, maxStepMip);                            // 升档上限相应降低
```
要点：① 步长额外受 `2^_MaxHiZMipLevel` 上限（步长不可能超过能采到的最大格子）；② `mipOffset` 让"格子 ≥ 跨度"⇒ 一步跨过的区域全被检查到，不漏；③ 基准步长 1 像素时 `mipOffset = 0`，与参考文章一致。
数例（span 400px、stride 1、mipCount 5 ⇒ `_MaxHiZMipLevel` 4）：`stepPixels ≈ 3.1`、`mipOffset = 2`、`maxStepMip = 2` ⇒ 最大步长 12.5px、可采 mip 4（格子 16px ≥ 12.5px ✓）、可达距离 ≈ 1600px。

- **建 Hi-Z 的其余待办**：mip 级数（`floor(log2(max(w,h)))+1` 或配 5~6）；格式 `R32_SFloat`+sRGB off+msaa1；生成时 point 采样、clamp；时机 = **所有不透明物之后（深度完整）、SSR trace 之前**，每帧一次；必须上传 `_MaxHiZMipLevel` 与把主图绑成 `_HiZTex`；临时图生命周期（`GetTemporaryRT(useMipMap:true)` 一帧建/放，或常驻）；可选"2 张临时图 ping-pong + CopyTexture 进主图 mip"以省掉 N 张临时图。
