## 用户总结 + 我的修正（2026-09-17，仍未改）

**用户提炼的规律（基本成立）**：**跟阴影有关**（PCSS 这类全屏 pass）用**几何法线**；**跟着色有关**（SSR/SSAO）用**着色法线**；前向/延迟都适用。
两条限定：① 前向的几何法线有两个来源 —— 物体模型（LitPass 逐物体）与（目前）`_CameraNormalsTexture`（prepass 写的也是几何法线）；② 落地时前向只有**一张**屏幕法线图，延迟天然有**两份**（GBuffer2 = 着色、深度重构 = 几何）⇒ 前向若要同时满足两类需求，得把 `DepthNormalsPass.hlsl` 改成写**着色法线**（= 走 `NormalTangentToWorld(GetNormalTS, normalWS, tangentWS)`，代价是 prepass 要多采法线贴图 + 切线），**同时 PCSS 必须改用深度重构**（否则 bias 变成"含着色法线"）。副作用：PCSS 两趟双边 blur 的"法线保边项"（`pow(dot(nC,nN),16)`）也会变成着色法线 —— 和延迟一致，但对去噪更不利（同面细节处权重下降）。
**"重建不完善"的优化选项**：① 步长 ±1 → ±2（更稳、轮廓更钝）；② 加"两轴候选都跨面就退回着色法线"的兜底；③ 根治只能 GT5（用户否）。

**⚠️ 视线方向翻正被否（用户质疑成立）**：虽然 `sign(dot(geo, viewDir))` 的符号在可见面上是全局一致的，但在**掠射面**（正是看长影子的地方）`dot → 0`，符号会**逐像素抖动** ⇒ 会闪。所以**不要用视线方向翻正**。
**替代方案**：PCSS 那条路**本来就有翻正**（见下），不依赖我们给的方向；延迟光照 pass 保持用一个"稳定"的参考（着色法线在掠射面也不抖，因为两者都贴着面法线）或按 uv 手性的**常数**翻正。⇒ **来源 A 的修法收敛为：只删 `dot > 0.25` 那道回退**（翻正参考不动）。

**"PCSS 不需要翻正"的意思**（我当时没说清）：`Shadows.hlsl` 的 `PCSSBiasNormal(surfaceWS)` 里，拿到 `surfaceWS.interpolatedNormal` 后立刻
`n *= (dot(n, _DirectionalPCSSLightDir) < 0.0 ? -1.0 : 1.0);` —— 它会**翻向光源**，所以我们传进去的法线朝哪边都无所谓（先翻后翻结果一样）。

## 用户确认"只测着色+阴影（关掉 PCSS/SSR）"时的口径（2026-09-17，未改代码）

**现状确认 —— 他说得对**：前向 bias 用**模型内插的几何法线**（`LitPass` 的 `surface.interpolatedNormal = input.normalWS`）；延迟 bias 用**屏幕深度重构**（我们那个 helper）。补充两点事实：① **shadow caster（画 shadowmap）根本不用法线**（只写深度），法线只用在校验/采样时的 **normal bias**；② PCSS 关掉（`pcss.enabled=false` ⇒ `useScreenSpaceShadow=false`）时两条路都走**逐像素 PCF**，都不采样屏幕空间阴影图。

**"完全一样"的现实边界**：模型内插法线是**光滑**的（顶点法线重心插值），深度重构是**逐像素平面拟合**（更"锐"、且有深度量化噪声）⇒ **平面几何上两者一致**，**曲面/掠射处不可能逐像素相等**；再加上延迟的 `_GBuffer2` 是 `ARGB2101010`（10 位量化）而前向 LitPass 用逐物体 float 法线 ⇒ 着色上也有极小差异。想真正一致只有 GT5 存真内插法线（用户否）。

**所以"改重建函数"的目标应是"更稳"而不是"更准"**：① 步长 ±1 → ±2（或 ±2/±3 混合，更平滑、抗噪声，轮廓略钝）；② 由"只挑一侧"改成"两轴中心差分 + 深度差限制跨面"（更平滑）；③ 加"两条轴都跨面 ⇒ 退回着色法线"的兜底。

### 检查：SSR 里的几何/着色法线问题（2026-09-17，只检查未改）

`ScreenSpaceReflection.hlsl` 里 `ScreenSpaceSceneNormal` 只有 **2 个使用点**：
1. **接收面反射方向**（`TracePassFragment` :363-367：`reflectDirVS = reflect(viewDirVS, normalVS)`）⇒ 用**着色法线**是**对的**（反射要跟着法线贴图走），而且前向 prepass 已改成着色法线 ⇒ 两条路口径一致 ✓ **没问题**。
2. **背面剔除**（`IsHitFrontFacing` :318-325，`dot(reflectDirVS, hitNormal) < 0` 判"是否从正面进入"）⇒ 这里属于**几何/可见性**用途，**严格说该用几何法线**；当前用着色法线 ⇒ 法线贴图很花的地方会误判 ⇒ 该有反射处出现黑点/闪烁。**这是一处真实的（轻微）遗留点**。
   修法：全屏 pass 里直接换成 `ScreenSpaceGeometricNormal(位置, 视深度, shadingNormal, uv)`（它已经在 `Fragment.hlsl`，成本 = 4 次深度采样 + 4 次重建，且只在**命中点**调用一次/像素、半分辨率 ⇒ 便宜）；`shadingNormal` 参数正好用刚采到的着色法线。
**另一处不对称（非法线，但同类"只有延迟有数据"）**：`TracePassFragment` :389-391 的 `receiverRoughness` 读 `_GBuffer3`，**前向固定按 0** ⇒ 前向反射不按粗糙度糊 mip（注释里已写明"先让反射保持清晰"）。

### 实施：SSR 背面剔除改用几何法线（2026-09-17，已做）

`ScreenSpaceReflection.hlsl` 的 `IsHitFrontFacing`：先采命中点的原始深度 + 着色法线（查天空/无效：`rawHitDepth < 1e-5 || dot(n,n) < 0.001` ⇒ 不剔除），再 `ScreenSpaceWorldPosFromDepth` 重建命中点 + `-TransformWorldToView().z` 得视深度，然后 `ScreenSpaceGeometricNormal(hitPosWS, hitViewDepth, shadingNormal, hitPixel)` 拿**几何面法线**判朝向（着色法线只当翻正参考）。开销 = 每命中像素 1 次重建 + 4 次深度采样，**不在 march 循环里**。文件头注释 ③ 也改成"反射方向用着色法线 / 背面剔除用几何法线"。

### 给用户的"该改哪儿"清单（2026-09-17，未改）

1. **必改**：删掉 `dot(geoNormal, shadingNormal) > 0.25` 那道回退（用户已认可）；**保留**退化保护（`dot(g,g) < 1e-12`，那是防 NaN 的必要项）。
2. **建议改（零成本、收益最大）**：现在是"**单侧估计**"（每轴只用一侧的 1 格做基准，另一侧的采样白采了）⇒ 改成 **中心差分** `cross(posR - posL, posU - posD)`：基准 2 格、对称 ⇒ 更抗深度噪声、曲面上不偏斜（更接近前向那条光滑内插法线）。**采样次数不变（现在本来就是 4 次、只用 2 个）**。需要一个小判据决定"用中心差分还是退回挑侧"（轮廓/折角处中心差分必然跨面）：**两侧的每格深度变化"同号且量级接近"** 才用中心差分（例如 `a=dR-dC`、`b=dC-dL`，判 `a*b > 0 && |a-b| < 0.5*(|a|+|b|)`），否则用现在的挑侧。不引入"和着色法线比"那种含义不明的阈值。

5. 退化分支返回 `shadingNormal`（路径相关，但该分支几乎不会发生）—— 可接受，先不动。

### ⚠️ 用户实测发现：**退化保护的阈值 `1e-12` 才是"前向/延迟不一致"的主因**（2026-09-17）

用户把 `if (dot(geoNormal, geoNormal) < 1e-12) return shadingNormal;` 去掉后，**前向/延迟（含着色法线的物体、无 PCSS/SSR）看起来完全一样了**。
**原因**：`dot(geo, geo)` 是**叉乘长度的平方**，而叉乘长度 = 两条边长**相乘**（单位 米²）。1 格的世界间距在 1080p/60°、1m 深度处 ≈ 1mm ⇒ 两条边乘积 ≈ 1e-6 m² ⇒ 平方后 ≈ **1e-12** ⇒ **近处像素大面积误触发**，返回 `shadingNormal`（前向=几何法线、延迟=着色法线，含义不同）⇒ 两条路分叉。
**修法**：阈值缩小几个数量级（如 `1e-24`），或只判 `geoLength > 0 / isfinite`；不要整个删掉（`normalize(0)` 会出 NaN）。
**追加**：用户实测"把 `1e-12` 改回来后，`(dot(geo, shading) > 0.25) ? geo : shading` 这行留着也看不出差别" ⇒ 问题**只**出在 1e-12 误触发。
**退化阈值细节（用户追问"1e-24 有精度吗 / 是不是等价于 ==0"）**：float 最小正规数 ≈1.18e-38 ⇒ 1e-24 完全可表示、不会下溢；正常几何下 |cross| ≥ ~1e-9 m²（1e-18 的平方），远大于 1e-24 ⇒ **该判据实际等价于"geoNormal ≈ 0"**，只在"两条边向量共线/一条为 0"（极端掠射退化）或 NaN/Inf 输入时触发，作用仅是防 `normalize(0)`。**更稳的写法：`if (!(dot(geoNormal, geoNormal) > 1e-24)) return shadingNormal;`** —— NaN 比较恒假 ⇒ `!假` = 真 ⇒ 连 NaN 输入一起兜住。
**我的建议：`0.25` 这行仍建议删掉** —— 它干的事就是"**退回着色法线**"，而着色法线正是两条路含义不同的东西（= 同一个分叉口，只是触发条件更窄：强法线贴图 + 掠射时 `dot` 会掉到 0.25 以下）。它想防的"法线乱飞"已由"挑近侧"机制解决；删掉后 `interpolatedNormal` 完全来自重构 ⇒ 彻底与路径无关。（真遇到"薄物体/掠射"零星斑点，应加**深度差兜底**，而不是退回顾着色法线。）
